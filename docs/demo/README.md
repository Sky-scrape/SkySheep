## 三、演示步骤安排（拍摄与制作流程）

四步可复现。制作脚本在作者工作区 `SkySheep-demo-live/`（含隔离环境、Playwright 驱动与合成脚本），
**未随仓库分发**——它们依赖本机的 Chrome、隔离 `SKYSHEEP_HOME` 与演示项目，直接放进仓库也跑不起来。
下面是完整流程，照做可以复刻一支同样的片子：

| 步骤 | 做法 | 产物 | 耗时 |
|---|---|---|---|
| 1. 隔离环境 | `demo/seed_demo.py`：复制一份 `.shotenv/skyhome` 到 `home/`（**绝不碰真实 `~/.skysheep`**），写入演示 `config.toml`（三位服务 + 占位 Key）、5 个项目 / 13 条定时产线 / 20 条今日运行账本、**纸墨皮肤** + 100% 缩放；另灌记忆地图需要的演化摘要（overview + 3 阶段）、会话标签与 4 条全局记忆；所有定时任务推到 46 分钟后（否则启动补跑会吃掉演示脚本） | `home/` + 演示项目 | ~2 s |
| 1b. 排今天这一班 | `demo/seed_today.py`：只重写「今天」的 `automation_runs`（06:05 起每 6 分钟一轮、共 17 轮，11 轮落在订单服务、含 2 次失败 / 1 次中断 / 1 轮在跑）并把定时任务下次运行推到 3 小时后。**录制当天必跑一次**：启动补跑会留下十几条「同一分钟」的碎片，回放按轮次演，碎片账本拍出来等于没播 | 今日账本 | ~1 s |
| 2. 起服务 | `demo/serve.py`：真实引擎 `create_app()` + 脚本化 `DemoProvider`。**按「系统提示词里的角色标记」分流**：主对话 / 圆桌 / 团队总管 / 团队成员（按名字）/ 对抗四阶段，各走各的队列；暴露 `/demo/state`、`/demo/reset?which=main\|rt\|team\|adv&skip=N` | `http://127.0.0.1:8812/` | ~3 s |
| 3. 录屏 | `demo/record.js`：Playwright（系统 Chrome，headless）+ 注入演示光标，九章各一个 `context`，真实点击/输入，关键动作写进 `marks.json` | `out/clips/*/*.webm` | ~12 min |
| 4. 合成 | `build.py`：按 marks 裁头 → 统一 1920×1080/30fps → 1920×1000 + 80 px 字幕条 → 拼接 → ASS 烧字幕 → numpy 合成原创配乐 → 混流 + 封面/SRT | MP4 + SRT + 封面 | ~6 min |

```bash
cd SkySheep-demo-live
python demo/seed_demo.py                                 # 1) 灌隔离环境
PYTHONPATH=../SkySheep/engine/src python demo/serve.py   # 2) 起服务（另开终端）
node demo/record.js                                      # 3) 录九章（可单录：node demo/record.js adv）
python build.py                                          # 4) 合成成片 + 字幕 + 封面
```

单章重录：接力章自带 `reset?which=main&skip=5`（只留六轮脚本），团队/对抗章各自 `reset?which=team|adv`；
工厂章上镜前先跑 `python demo/seed_today.py`（否则当天的账本是补跑碎片，回放没内容）；
记忆地图章依赖 `home/ui.json` 的面板宽度与页签，重录前把 `right_w` 改回 420、`right_tabs` 设成
`["files","tasks","agenda","auto","relay"]`，画面才和前后章衔接。

## 五、真实性边界（必须说清楚的四件事）

1. **模型说的话是脚本回放的，其余都是真的。**
   `DemoProvider` 按脚本吐文本与工具调用，带 token 节奏；除此之外全走真实代码路径：
   工具真执行、权限门真拦截、diff 由引擎生成、写文件真落盘、检查点真回滚、
   圆桌/对抗/接力的编排都由引擎真实跑、定时任务真写进 SQLite、记忆地图的数字来自真实会话与 token 记录。
2. **团队这一段是「用户当总管」的真实操作。**
   片中你看到的是：建队 → 登记工单 → 派工 → 转待验收 → 通过 → 交付，全部是真实的工单状态机与频道消息。
   但**队员的自动报告在这套脚本化演示环境里没有接真实模型**（脚本侧未提供成员唤醒内容），
   所以片中没有成员发言，是靠「转待验收 → 通过」推进的；真实使用时队员被派工后会自动产出报告。
3. **对抗的四段 JSON 是本片的关键脚本。**
   发现者输出候选清单、调查员输出裁决、建议者输出修复、裁判输出报告，格式必须能被引擎解析——
   这三段 JSON 是按引擎的解析契约手写的，内容是这份代码里**真实存在**的三处问题
   （`len(_ORDERS)+1` 撞号、重复单只 warning、遍历可变字典）。
4. **工厂与记忆地图里的历史是「为演示灌入的数据」。**
   项目、定时产线、今天 17 轮运行记录（`seed_today.py` 重排）、演化摘要三阶段与 4 条全局记忆，
   都由种子脚本写入；片中成品垛数量、回放轮次 / 钟点、时间线会话条数、图谱节点，
   都是这些真实记录算出来的（读取/统计/回放/布局逻辑是真的，数据内容是演示数据）。

## 六、二次使用建议

- **官网首屏**：可直接用 MP4；自动播放另导无声 WebM 加 `muted playsinline loop`（本片无旁白）。
- **短视频平台**：建议按章节剪 5 条 15–25 秒竖版：①工具真跑 ②diff + 撤销 ③圆桌 ④对抗 ⑤接力。
- **内部分享**：如需旁白，可照第二节的字幕列录制（语速 220–250 字/分），配乐再降 6 dB；
- **换配乐**：改 `build.py` 的 `build_music()`（和声表 `CH`、旋律动机 `MOTIF`、`BPM` 三个地方），重跑 `build.py` 即可，画面不重录。
- **需要无字幕版**：`build.py` 最终一步去掉 `-vf "ass=subs.ass"` 即可。
- **想换深色**：把 `home/ui.json` 的 `"theme"` 改成 `"night"`（夜墨）重录，卡片不用改。

## 七、已知小瑕疵（如实列出）

- 团队章节点「交付」后卡片自动收起，片中用「展开 → 频道」补看了一眼留痕；
- 对抗章节的裁判阶段有约 20 秒纯流式，字幕分了三段铺满，仍是最长的一段；
- 右侧面板的页签会随着章节推进累积（接力 / 记忆地图…），是真实使用痕迹，没有刻意清空；
- 录屏段为 1920×1000 画面 + 80 px 字幕条，界面比原生 1080p 小约 7%。
