# 分发上架指南（签名 · winget · Scoop）

> 本文管「Release 发完之后，往哪些渠道上架、怎么上架」。发一版本身的纪律见
> [发布清单.md](发布清单.md)；安装包被 SmartScreen 拦截的用户指引见
> [smartscreen-说明.md](smartscreen-说明.md)。
>
> 现状：安装包**未签名**（README 路线图「代码签名分发」尚未落地）。因此本文的推荐
> 顺序是：先做 Scoop（§2，无门槛）→ 签名（§3，需付费/账号）→ 再上 winget（§1，
> 社区仓库对未签名安装包有被评审驳回的风险）。标 **需人工** 的步骤涉及账号开通、
> 付费或仓库管理员权限，不在可自动化范围内。

## 0. 前置事实（都写死在现有实文里，本文只引用不新增）

| 事实 | 出处 |
|---|---|
| 仓库是 `Sky-scrape/SkySheep` | git remote；`engine/tools/installer.iss` 的 `MyAppURL` |
| 安装包名 `SkySheep-<版本>-setup.exe` | `installer.iss` 的 `OutputBaseFilename`（版本由 `#define MyAppVersion` 决定） |
| 校验附件 `SkySheep-<版本>-setup.exe.sha256`，内容 `<64位哈希>␣␣<安装包名>`（两个空格 + 文件名尾巴） | [发布清单.md](发布清单.md) §4；实测样例 `engine/installer/SkySheep-2.3.0-setup.exe.sha256` |
| 应用内更新按「安装包名 + .sha256」同目录探测校验和，有则必校 | `engine/src/skysheep/server/backend_parts/remote.py` 的 `_fetch_setup_sha256` |
| 版本号一致性由脚本机械校验（pyproject / `__init__` / installer.iss / CHANGELOG 最新发布条目 / 两份 README 路线图标记） | `engine/tools/check_versions.py` |

## 1. winget（社区仓库上架）

### 1.1 manifest 三件套

- PackageIdentifier 定 `Sky-scrape.SkySheep`（Publisher 段与仓库 org 一致）；
- 三份 YAML 放 `manifests/s/Sky-scrape/SkySheep/<版本>/`（目录首段是 Publisher 首字母小写）；
- **推荐用 `wingetcreate new <InstallerUrl>` 生成骨架再校对**（它会顺手探测 ProductCode、
  选最新的 SchemaVersion）；下面是手写模板，SchemaVersion 以生成器输出为准。
  `<版本>` / `<哈希>` 两处占位符每次发版更新。

`Sky-scrape.SkySheep.installer.yaml`（安装清单）：

```yaml
PackageIdentifier: Sky-scrape.SkySheep
PackageVersion: <版本>
InstallModes:
  - interactive
  - silent
  - silentWithProgress
UpgradeBehavior: install
Installers:
  - Architecture: x64
    InstallerType: inno
    InstallerUrl: https://github.com/Sky-scrape/SkySheep/releases/download/v<版本>/SkySheep-<版本>-setup.exe
    InstallerSha256: <哈希>   # 与 .sha256 附件首段一致，见 §1.3
    InstallerSwitches:
      Silent: /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
      SilentWithProgress: /SILENT
      # 本安装器支持 /CURRENTUSER 降权（installer.iss 的 PrivilegesRequiredOverridesAllowed），
      # winget 默认按 Scope 走 machine，无需额外开关
    Scope: machine
    # 手写时建议补 ProductCode（Inno 的卸载注册表键 = AppId + "_is1"，AppId 见 installer.iss）；
    # wingetcreate 生成时会自动从安装包里探测：
    # ProductCode: '{7C1B6E9A-52C4-4B7D-9A34-A1B2C3D4E5F6}_is1'
ManifestType: installer
ManifestVersion: 1.9.0
```

`Sky-scrape.SkySheep.locale.yaml`（默认语言清单；产品中文优先，与安装器首个
MessagesFile 一致）：

```yaml
PackageIdentifier: Sky-scrape.SkySheep
PackageVersion: <版本>
PackageLocale: zh-CN
Publisher: Sky-scrape
PublisherUrl: https://github.com/Sky-scrape
PublisherSupportUrl: https://github.com/Sky-scrape/SkySheep/issues
PackageName: SkySheep
PackageUrl: https://github.com/Sky-scrape/SkySheep
License: MIT
LicenseUrl: https://github.com/Sky-scrape/SkySheep/blob/main/LICENSE
ShortDescription: 开源桌面 AI Agent 工作台
Description: SkySheep 是一个开源桌面 AI Agent 工作台：Python asyncio 引擎、pywebview 桌面壳、零构建前端，本地运行、权限门控。
Tags:
  - ai
  - agent
  - llm
  - chatbot
ManifestType: defaultLocale
ManifestVersion: 1.9.0
```

`Sky-scrape.SkySheep.yaml`（版本清单）：

```yaml
PackageIdentifier: Sky-scrape.SkySheep
PackageVersion: <版本>
DefaultLocale: zh-CN
ManifestType: version
ManifestVersion: 1.9.0
```

### 1.2 提交流程（每个版本一个 PR）

1. **前置**：建议先完成 §3 签名。未签名安装包要过社区仓库的恶意软件扫描与实测安装，
   有被驳回或被机器人标记的风险。
2. Fork `microsoft/winget-pkgs`。**需人工**：提交账号需满足仓库的贡献者要求
   （历史上有 GitHub 账号注册时长门槛），以仓库 PR 模板与文档为准。
3. 在 fork 里建 `manifests/s/Sky-scrape/SkySheep/<版本>/`，放入 1.1 的三份 YAML：
   首发是新增整个包目录，后续版本是新增版本目录。
4. 本地校验：`winget validate <目录>`；再实测 `winget install --manifest <目录>`。
5. 开 PR：标题首发 `New package: Sky-scrape.SkySheep version <x.y.z>`、
   更新 `New version: Sky-scrape.SkySheep version <x.y.z>`（标题约定以仓库文档为准）。**需人工**。
6. 跟进 `@winget-pkgs` 校验机器人与维护者意见，按需修改直至合并。**需人工**。
7. 合并后验证：`winget search SkySheep`、`winget show Sky-scrape.SkySheep`。

### 1.3 版本发布后的联动检查点

- [ ] GitHub Release 已发且资产可下载（发布清单 §4 的「发布后验证」先过）。
- [ ] `InstallerSha256` == 同名 `.sha256` 附件首段哈希 == `Get-FileHash` 实测值。
      取哈希：`Get-FileHash engine\installer\SkySheep-<版本>-setup.exe -Algorithm SHA256`。
- [ ] `PackageVersion` 与 `python tools/check_versions.py` 校验的五处版本一致。
- [ ] `InstallerUrl` 可下载（Release 资产 URL 200）。
- [ ] **签名启用后的版本：哈希必须取自签名后的 exe**（签名会改变哈希，见 §3.4）。
- [ ] 每个新版本都要提一个新的 manifest PR（winget 不自动跟进 GitHub Release）。

## 2. Scoop（自建 bucket）

无评审、不依赖第三方仓库：建一个自己的 bucket 仓库，例如 `Sky-scrape/scoop-bucket`
（建仓库 **需人工**，之后 manifest 更新直接推送即可）。

### 2.1 目录结构

```
scoop-bucket/
├── bucket/
│   └── skysheep.json      # manifest，文件名即安装名（scoop install skysheep）
└── README.md
```

用户侧使用：

```powershell
scoop bucket add skysheep https://github.com/Sky-scrape/scoop-bucket
scoop install skysheep
```

### 2.2 manifest JSON 模板

`bucket/skysheep.json`（`<版本>` / `<哈希>` 占位符；本仓库自带
`engine/tools/make_scoop_manifest.py` 可自动生成整份文件，见下）：

```json
{
    "version": "<版本>",
    "description": "开源桌面 AI Agent 工作台：Python 引擎 + 桌面壳 + 零构建前端",
    "homepage": "https://github.com/Sky-scrape/SkySheep",
    "license": "MIT",
    "architecture": {
        "64bit": {
            "url": "https://github.com/Sky-scrape/SkySheep/releases/download/v<版本>/SkySheep-<版本>-setup.exe",
            "hash": "sha256:<哈希>"
        }
    },
    "innosetup": true,
    "shortcuts": [
        ["SkySheep.exe", "SkySheep"]
    ],
    "checkver": "github",
    "autoupdate": {
        "architecture": {
            "64bit": {
                "url": "https://github.com/Sky-scrape/SkySheep/releases/download/v$version/SkySheep-$version-setup.exe",
                "hash": {
                    "url": "https://github.com/Sky-scrape/SkySheep/releases/download/v$version/SkySheep-$version-setup.exe.sha256",
                    "find": "^([a-fA-F0-9]{64})"
                }
            }
        }
    }
}
```

要点：

- `innosetup: true`：让 Scoop 用 innounp **解包**安装器而不是真跑安装——免管理员、
  不写注册表，卸载即删目录且不碰 `~/.skysheep`，与本项目「卸载不碰用户数据」的现状一致。
  innounp 对较新版 Inno 的兼容问题，用户可 `scoop install versions/innounp-unicode` 绕过；
  若解包路径有问题，退路是 `installer` 节传 `/VERYSILENT /NORESTART` 静默安装（需管理员，不推荐）。
- `architecture` 只留 `64bit`：安装器 64 位优先（installer.iss 的
  `ArchitecturesInstallIn64BitMode=x64compatible`），Scoop 用户基本都在 64 位 Windows。
- `checkver: "github"` 跟 `releases/latest` 的最新 tag；`autoupdate` 的 `hash` 直接读我们
  发版本来就带的 `.sha256` 附件——**bucket 的校验和与发布链路天然联动**，不用维护第二份哈希。
- 配套工具：`uv run python tools/make_scoop_manifest.py`（在 `engine/` 下执行）读
  pyproject 版本与 `engine/installer/` 里的 `.sha256` 附件，输出整份 manifest（当版哈希
  已填好）；`--out <路径>` 另存为 UTF-8 文件。**签名启用后要重新生成**，确保哈希取自签名后的产物。

### 2.3 与 release.py 的衔接（建议，暂不实现）

建议后续 `engine/tools/release.py` 的 `--upload` 阶段在传完 Release 资产后顺手更新
bucket manifest：调 `make_scoop_manifest.py` 生成当版 JSON（打印 diff 或直接写到 bucket
仓库工作区），把「发版 → bucket 更新」压成一步。本文只记建议，不做实现；bucket 仓库的
推送动作仍属 **需人工**。

## 3. 签名

### 3.1 三条路一句话对比

| 方案 | 一句话 |
|---|---|
| **Azure Trusted Signing**（2025 起更名为 Azure Artifact Signing） | Basic **$9.99/月**（含 5,000 次签名/月，超出 $0.005/次；Premium $99.99/月含 100,000 次），密钥由微软托管不出 HSM；**个人开发者目前仅限美国/加拿大**，组织限美国/加拿大/欧盟/英国，开通需身份验证——对个人开源项目是最便宜的月付路线（开通 **需人工**） |
| 自购 EV 证书 | 数千元/年 + 硬件 U 盾（或云 HSM），SmartScreen 信誉立竿见影，但通常要求公司主体（购买与续期 **需人工**） |
| SignPath | 开源项目可申请 Foundation 免费额度 **需人工**，代价是签名与构建链路绑定其服务 |

提醒：Trusted Signing 发的是标准（OV 类）证书而非 EV，**不是买了签名 SmartScreen 就立刻
放行**——「已验证的发行者」信誉要积累一段时间，[smartscreen-说明.md](smartscreen-说明.md)
的放行指引在此期间仍然有用。

### 3.2 Trusted Signing 开通概览（**需人工**）

1. Azure 订阅与可用区确认（注意服务可用区域与账号主体所在地的匹配）；
2. 建 Artifact Signing 账户 + 公共信任（Public Trust）证书配置；
3. 提交身份验证（组织或个人；个人目前仅美加）；
4. 拿到 Endpoint / CodeSigningAccountName / CertificateProfileName 三要素，写进 signtool
   用的 metadata JSON（Dlib 的 `/dmdf` 参数）。

本节是量级概览，开通细节以 Microsoft Learn「Trusted Signing」文档为准。

### 3.3 installer.iss 接入点（注释形态，默认未启用）

Inno 的签名指令放 `[Setup]` 节；**SignTool 的具体命令不进脚本**——它定义在 Inno Setup IDE
的 Tools→Configure Sign Tools 里，或编译时用 `ISCC /S"<名字>=<命令>"` 传入。给
`engine/tools/installer.iss` 预留的接入形态（保持注释，启用时取消注释并配置 SignTool）：

```ini
[Setup]
; —— 代码签名（默认未启用；启用步骤见 docs/分发上架指南.md §3）——
; SignTool=TrustedSigning      ; 名字对应 /S"TrustedSigning=..." 或 IDE Configure Sign Tools 里的条目
; SignedUninstaller=yes        ; 卸载器一并签名（随最终 setup 内嵌）
; SignToolRetryCount=2         ; 签名失败自动重试次数
; SignToolRetryDelay=1000      ; 重试间隔（毫秒）
```

SignTool 命令示例（Trusted Signing 的 signtool + Dlib 形态，示意；`$f` 是 Inno 传给签名
工具的文件占位符，必须保留）：

```
ISCC /S"TrustedSigning=signtool.exe sign /fd SHA256 /dlib <Azure.CodeSigning.Dlib.dll 路径> /dmdf <metadata.json 路径> $f" tools\installer.iss
```

### 3.4 签名对现有链路的影响（重要）

- Inno 在**编译完成后**对最终 setup.exe 签名，因此签名**会改变安装包哈希**：
  `.sha256` 附件、winget `InstallerSha256`、Scoop `hash`、Release 正文可读哈希，全部必须
  取自**签名后**的 exe。顺序固定为：打包 → 签名 → 生成 `.sha256` → 上传 Release → 上架。
- 版本号不因签名变化，`check_versions.py` 与应用内更新链路（按文件名拼 URL）不受影响。

## 4. 上架节奏与版本联动检查表

节奏跟着发布清单的双周一版走：**上架动作排在 Release 之后**，同一渠道每个版本一个
manifest 变更（winget 一个 PR，Scoop bucket 一次推送）。同版发现哈希错误：不 `--clobber`
重传，按发布清单 §4 删资产重传后，同步更新 winget/Scoop 的哈希。

发一版逐条打勾：

- [ ] 版本号五处一致：`python tools/check_versions.py` 退出码 0
- [ ] 安装包名 `SkySheep-<版本>-setup.exe` 三处同版：Release 资产名 == winget `InstallerUrl`
      文件名 == Scoop `url` 文件名（都由 installer.iss 的 `MyAppVersion` 派生，不会漂）
- [ ] 哈希三处同源同值：`.sha256` 附件 == winget `InstallerSha256` == Scoop `hash`，
      且等于**最终产物**（签名后）的 `Get-FileHash` 实测值
- [ ] manifest 两处版本号一致：winget `PackageVersion` == Scoop `version` == 五处版本
- [ ] Release 资产（exe + `.sha256`）已上传、下载链接 200、`releases/latest` 302 到本版 tag
- [ ] 应用内「检查更新」回归通过（发布清单 §4 末条）
- [ ] Scoop bucket 更新并推送 **需人工**；装一次 `scoop install skysheep` 验证
- [ ] winget manifest PR 提交并跟进合并 **需人工**；合并后 `winget search SkySheep` 验证
