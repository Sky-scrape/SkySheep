# 工厂设计

> 状态：一期主体、二期除历史回放外的能力及 §15 三期增补已有实现（当前工作区，非发布承诺）。
> 本文是「工厂」功能的概念来源；§12 保留验收要求，不代表每项已完成实机验收。术语已并入 `docs/界面术语表.md`。
> 设计原则：观战不改执行语义；跨项目不等于跨权限；像素场景是一扇窗，不跟随六套主题换色；能复用的调度设施全部复用（§11）。

## 1. 定位

**工厂 = 跨项目的自动化观战台 + 总厂调度台。**

把所有项目的自动化摆进一个像素风俯视场景：每个项目是一座**厂区**，每条自动化是一条**产线**，每一次真实运行是一枚沿传送带走动的**包裹**。你可以在这里看着它们跑，也可以从这里给任意项目派活。

| | 自动化页（现有） | 工厂（本设计） |
|---|---|---|
| 范围 | 当前项目 | 全部项目并列 |
| 单位 | 任务行（定时 / 编排） | 一次运行（包裹） |
| 形态 | 清单 + 表单 | 像素场景 + 常驻监控面板 |
| 时效 | 按需查看 | 常驻观战，实时 |
| 用途 | 配置自动化 | 观战、派工、发现异常 |
| 写操作 | 增、删、改、跑 | 只派工（运行 / 启停 / 建轻量定时产线） |

与既有功能的关系：

- **不是新的执行模型**：每条产线背后都是现有的 `cron_tasks` / `pipelines`，调度仍走 `_cron_pass` 与 `_pipeline_advance`，权限仍走各自的 `HeadlessGate`。工厂只是把它们「翻译」成看得懂的场景。
- **与记忆地图分工**：记忆地图看**过去**（项目演化的叙事），工厂看**此刻**。
- **与圆桌 / 团队 / 对抗分工**：那三者是一个会话内的多模型协作；工厂是多个项目之间的自动化。
- **与接力工作台分工**：接力靠人主动交棒，工厂靠机器按点 / 按需派活。

## 2. 对象体系

### 2.1 映射

| 引擎实体 | 工厂叫法 | 模型形象 | 备注 |
|---|---|---|---|
| `projects` | 厂区 | 围栏场院 + 灰钢厂房 + 锈色筒仓 + 高架传送带 + 戴安全帽的小羊工头 | 快聊与「远程连接」哨兵项目不建厂区 |
| `cron_tasks` | 产线（单机） | 一台带色带与状态灯的金属机台 + 自己的传送带支线 | 一台机器反复干同一种活 |
| `pipelines` + `pipeline_nodes` | 产线（装配线） | 三个小工位串在一条短带上 | 一条线上多个工位，产出可被下游工位读取 |
| 一次运行（cron run / node run） | 包裹 | 在传送带上行进的矿车式纸箱，颜色按产线稳定哈希，有地面影子 | 有编号，可点开 |
| 运行产出（会话 / 报告 / 结果文件） | 成品 | 落木托盘码垛 | 点击打开会话或产出文件 |
| `_cron_pass` / `_pipeline_advance` | 调度厅 | 石台 + 钢塔 + 玻璃顶 + 旋转雷达，20s / 5s 一圈 | 转速与真实扫描间隔一致，厅顶挂「在转 N 件」 |
| 运行失败 | 回炉 | 包裹变红、沿返程带退回调度厅 | 机台故障灯亮起 |
| 空产出 | 空箱 | 灰白，停在带尾 | 不做惩罚性动画 |
| 产线暂停 / 厂区不可用 | 停工 | 厂区挂红牌 | 停工期间不派活 |

### 2.2 术语边界

- 不叫「任务」——「任务」已是右面板容器词（子代理 / 步骤 / 事项）。
- 不叫「工单」——团队专用。
- 不叫「流水线」——引擎概念（`pipelines` 表、编排），界面上说「产线」「装配线」。
- 「工厂」与「工作台」（接力）、「工作目录」（路径）严格区分。

## 3. 界面结构

工厂是**第三顶层视图**，与「对话 / 设置」并列，左侧导航直达。

```
┌──────────────────────────────────────────────────────────────┐
│            [运行中 2] [排队 3] [需留意 0] [今日做成 6]   10:30 周三 │
│ ┌──────────────┐                                             │
│ │ 自动化监控     │                                             │
│ │ ▾ 项目 A  3 线 │            调度厅                          │
│ │  ● 日报  运行中 │      ╭──────────────╮     ▣ 厂区 B        │
│ │  ○ 巡检  待机   │      │  在转 5 件    │    ╱ 传送带        │
│ │ ▸ 项目 B  2 线 │      ╰──────────────╯     ▣ 厂区 C        │
│ └──────────────┘                                             │
│         [全景] [名牌] [全部运行]                                  │
└──────────────────────────────────────────────────────────────┘
```

- **顶部计数条**：运行中 / 排队 / 需留意 / 今日做成。
  - 运行中：`automation_runs.status = running` 的条数。
  - 排队：到点但超过 `max_parallel_runs`、等下一轮扫描的定时任务，加上编排里依赖已满足、正在等全局并发额度的节点数。
  - 需留意：孤儿任务 + 上次失败 + 运行中断 + 空产出 + 有工具被拦（`partial`）+ 到点被跳过 + 停工厂区，点开逐条列出；同一产线只留等级最高的一条。
  - 今日做成：本地当天 0 点以后 `outcome = ok`（或旧行无 outcome 时的 `status = done`）的运行数；`partial` / `empty` / 人工判负都不算。
- **右上**：真实时钟 + 星期日期 + 现实天气胶囊（开启后显示城市 / 天气 / 气温）。天气默认关（见 §9）。
- **左侧常驻监控面板**（可折叠）：顶部一条筛选（`全部 / 在跑 / 需留意 / 停工` + 关键词搜索，匹配厂区名或产线名；命中厂区名时整座厂区放行）。下面按厂区分组，组头「项目名 · N 条产线 · M 条在忙」+ 两个厂区级批量按钮（`▶` 派工 / `⏸` 暂停，样板厂一律禁用）；每行一条产线：状态灯 + 名称 + 触发方式 / 下次时间（在跑时改为「在跑 <工具名>」）+ 右侧状态（运行中 3 分 / 排队 2 / 待机 / 停工 / 上次失败 / 上次叫停）。点击行打开对应任务详情并高亮机台，镜头保持固定；`↑ ↓ / Home / End` 可在面板内逐行移动焦点，`Enter` 打开（面板是画布的等价入口）。筛选只作用于这块面板，场景始终画全部厂区。窄屏下这台面板就是主体。
- **中央画布**：调度厅居中，厂区排外环（§4.1）。
- **底部工具栏**：全景 / 名牌开关 / 全部运行，不提供拉近与拉远。
  - **固定全景**：固定 45° 视角，完整园区和外围设施的取景边界居于画布正中；按可用窗口自动计算合适比例，窗口尺寸或面板宽度改变时重新适配，鼠标拖动、滚轮及任务点击均不改变镜头位置或比例。点厂区头进入聚焦档后，用「全景」按钮或 Esc 回到全景；保留任务点击与悬停提示。
- **右侧抽屉**：点包裹看运行详情（任务、项目、触发方式、起止、耗时、状态、结果摘要、打开会话 / 产出）；点机台看最近 20 次运行与「立即运行 / 暂停」。
- **窄屏（≤860px）不画场景**：自动切「车间列表」——厂区折叠卡 + 每条产线一行状态灯，信息不丢；场景只在桌面宽度呈现。

## 4. 场景与像素渲染

### 4.1 世界与布局

- 世界以**瓦片**为单位（32×16 菱形等距格），调度厅在地图中心。
- 世界按隐藏的 **3×3 等距网格**排布：调度厅占中心格，项目厂区占外围八格，沿菱形平台的两条轴投影，不绘制格线。按网格四角、再四边的固定槽位填充，空格保留；新增项目不移动已有厂区。平台以调度厅为几何中心，并完整包住所有厂区坪尖角；超过 8 个项目继续向外扩 5×5、7×7 外圈。
- 厂区是一块带围栏的场院平台，尺度按产线数分三档：1~2 条产线 = 小场院，3~5 条 = 中场院，6 条以上 = 大场院；坪面半宽从 104 起，按建筑、筒仓与机台占地的内切矩形放大，四角不压出菱形坪沿。单厂最多画 6 台机台，其余在名牌上标 `+N`。
- 高架传送带从调度厅外墙直达厂区侧面入口，避免绕过其他厂区；入口再接前场机台，包裹与带面统一为 12 单位高度，带下有土路、支腿与投影。
- 厂区排序变化（用户拖拽侧栏）时整图重排，不做物理碰撞模拟。

### 4.2 等距建模与像素化

- **低分辨率内部缓冲**：按 CSS 尺寸的 1/2 渲染（最小 320×180），放大时 `imageSmoothingEnabled = false` + `image-rendering: pixelated`，得到硬边像素；镜头位置取整，避免半像素抖动。
- **所有物件都是三维模型**：建筑/仓库/机台用盒体（底面中心 + 半宽 + 半深 + 高度），筒仓用圆柱（半径 + 高度 + 箍圈 + 爬梯），传送带用带面 + 桁架支腿，调度厅是石台 + 钢塔 + 玻璃顶 + 雷达。渲染按「顶面亮 / 左面中 / 右面暗」三块面着色，按屏幕底线排序（画家算法），并在地面留下投影。盒体建筑再叠勒脚、墙面分缝、窗台、雨棚、门灯、落水管与檐口 / 女儿墙；平顶补天窗、屋顶机组与检修口，锯齿顶加压脊与檩条；高体量补检修爬梯，放大后还能看到筒仓仓身梯与提升机塔外梯。
- **建筑群多样**：每个项目按稳定哈希取一种完整厂区，而非共享底模只换屋顶：重工铸造厂用高锯齿厂房、双烟囱与单筒仓；物流集散仓用低矮长仓、卸货雨棚、集装箱排与卡车；垂直加工塔用窄高塔楼、低翼和高位连桥；联排制造坊用三座错落钢锈车间；数据机房用双机房、屋顶散热阵列与地面冷却柜；退台研发园用玻璃退台、独立实验楼与小庭院；双跨装配厂用两座大进深大厅、架空桁架和卷盘料场；罐区精炼站用紧凑控制楼、四座高低反应罐和管廊。各组主附楼数量、位置、长宽与物资区均不同，不再统一配置右筒仓、左集装箱或烟囱；共用灰钢、锈色、沙地与暖窗材质。远景另有储罐、仓库、输电塔、卡车与雾化工业天际线，低对比、只作背景，不与厂区抢主体。厂型只是视觉造型，不推断项目用途。
- **结构与分区**：厂区保持「后场建筑、前场任务」的公共边界，真实任务机台、成品盘与工头不随装饰厂型替换。建筑占地限制在各自菱形坪内，烟囱、罐区、冷却柜、庭院与装卸区按厂型选配。调度厅与项目入口保持直线连接，入口再接前场枢纽，短支线停在机台身后。屋顶用和墙体相同的等距顶面参数生成，三段锯齿面共边连接。铺装层先于所有实体绘制，传送带按不超过 14 单位的短段排序，避免整条带面按中心深度覆盖其他建筑。名牌按主体高度定位，不跟随独立烟囱或反应罐抬高。
- **地表与氛围**：整片厂区采用贴地园区，不再绘制厚岩壁、岩层线或崖底投影；九宫格边缘保留薄路沿，外围道路与厂区处于同一地面；混凝土厂区坪与沙地分色，坪面补环缝、坪缘石、角柱、安全黄线、通道、轮胎痕、地井格栅与入口斑马线，前后两缘加围栏，铁路和货车沿前沿布置。日位固定在左上，与墙面受光（左面中、右面暗）和右下投影一致；远景工业带缩小后移，并在远景与主体之间压一层阶梯薄雾。烟囱与冷却塔冒烟、空气里有粉尘，夜间有窗光、星点、传送带边灯与月盘，台面按月光提亮一档；路灯另有地面光池，料场两盏冷白投光扫向筒仓与提升机塔，棚口、磅房和大门用暖光，卡车亮起前后灯。标签使用逻辑 CSS 尺寸，避免全局界面缩放后名牌与模型错位；机台名只在比全景更近时才出现。
- **大型公用设备**：非项目设施沿九宫格外沿成组布置：冷却塔与泵房位于右后外侧，仓库、储罐与输电塔分布在左右外沿，另增带变压器与绝缘子的变电站、三腿架高水塔和锯齿顶维修库。左侧外沿再补一组物资 / 检修场（近景配色，按独立场坪分散布置的平顶库房、双坡工棚、储罐与小龙门吊），把外圈后勤带与料场之间的空沙地填起来。左上补后勤建筑群（退台后勤楼、检修车间、物资库、门房与货车），右上补能源建筑群（锯齿能源厂房、泵房、双储罐与短管廊）；两组各自使用固定锚点，整组移动保持建筑与管道连接，不生成项目名牌、任务或运行状态；外围圈扩大时同步外移，避免远离主体或侵入项目格。管廊、转运桥与烟口随所属设施整组移动，保持连接。双冷却塔直接落在沙地上（不铺机组坪），用分段收腰曲面建模，带开口塔喉、分面明暗、筋线、进风支柱、爬梯与蒸汽；两塔沿同一方向排开，泵房与两段短管廊把机组接回地面。高架传送桥退到远景工业带并做雾化，不穿过机台区、也不压在厂区上方。它们是场景设施，不表示跨项目供货关系，也不伪造运行状态。全景取景同时计入设备占地与塔体高度，避免裁切。
- **前场料场与罐区**：在九宫格前的开阔沙地上补两组近景建筑，**直接落在沙地上、紧贴前缘公路外侧**，把全景里最容易空着的前缘填起来。两组都紧贴公路外侧：罐区按「贴路一排是主体、南面一排是装卸配套」摆；**料场整组顺着公路方向排**——组内一律用「沿公路 (u) / 纵深 (v)」两条轴表达，`v` 越大越远离马路（老版拿世界 x / y 当排布轴，而前缘公路是斜的，摆出来整排与马路不平行、最高的筒仓群反而压在最靠路的一侧）。西侧料场用两条马路方向做 L/R 两轴：L 沿近侧公路，R 沿另一条路；场内由后往前三排——**后排是筒仓群**（三只仓沿 L 排开，提升机塔在右端，塔顶到中排棚脊的运煤线连成一体），**中排是拱顶煤棚**（开口朝公路，两堆露天煤分列左右），**前排是地磅 + 排队卡车 + 磅房**（地磅在前段，卡车朝公路出口排队）。三排都沿 R 方向展开，和围栏共用同一坐标系。料场另加一道**矮围栏**（后缘长栅栏沿 L，左右两条翼栅沿 R，前侧完全敞开）把三排圈在同一个平行四边形场院里；底面仍是沙地、不铺场坪，排与排之间留出空档，等距投影下后排的高塔难免压住中排下缘，靠这道围栏读出「一组 + 三排」。场内左侧再摆两堆露天煤、地磅（黄黑秤台 + 双端警示条 + 计量立杆）、排队卡车与磅房；这些部件放在煤棚左侧的开阔场院，避免等距投影下被棚顶挡住。东侧罐区：**湿式气柜**（三节套筒互相套着升降，外套导架与外梯）+ **循环水池**（下沉水面、池壁、溢流堰与两侧栏杆）+ 泵房 / 短管廊 编成一排，**装车台 + 罐车整块放到这一排前缘以南**（棚子在 h=15 处张开，压到气柜或水池底上就看着粘在一起），**火炬塔**（细高塔身、燃烧头与三只引火管，昼夜都有火苗与烟柱）站东端。两组**脚下不铺场坪**（要的就是落在沙地上），所以贴近关系由实测决定：整组建完量一次「最靠路那面墙沿外法线到公路中线的距离」，再把整组挪到 `ROAD_CLEARANCE`（14 单位，一条排水沟），改布局不用回来手改常数；位置仍按当前台地尺寸算（公路走向就是台地前缘那两条边），台地随项目变多长大时跟着挪，锚在 `plateauAligned` 上不再按环数二次位移。它们不标记 `bg`——`bg` 会被雾化调色板压成远景色，摆在近景会发灰；只做装饰，不产生运行状态。
- **前场道路**：只有园区那条主干道（贴台地前缘的 V 形），两端顺走向各自延长出去做出图的方向感。两组厂外建筑另加的场内道（一条竖直穿过场地、跨过主干道）实拍下来像两根立在沙地上的长杆，已整条删除——现在前场除了主干道不再有别的路面，两组就是直接落在路外侧的沙地上。
- **动画帧率 10fps**：包裹沿带面移动、传送带纹理滚动、烟团逐帧上升、雷达旋转。镜头平移与缩放走 rAF，保持流畅；场景本身保持「游戏机」手感。
- 世界坐标与视口解耦：完整园区自动居中取景，适配后锁定比例，禁止手动缩放和平移；窗口尺寸变化或重开视图时重新适配（进厂区聚焦后按 Esc /「全景」回全景）。

### 4.3 调色板与昼夜

- 约 38 色，**昼 / 夜两套**：昼盘是黄金时刻的沙漠工业区（暖沙、灰钢、锈色筒仓、暖窗），夜盘是钢蓝暮色（冷钢、锈色、暖黄窗光、星点）。
- 由「现实本地时间」决定，**不再跟随主题明暗**：06:00–18:00 取昼盘，其余取夜盘；开启现实天气后优先用当地日出日落（服务端 `is_day`）判断昼夜。关闭 `[factory] ambient` 时固定昼盘。
- **场景不跟随六套主题换色**：六主题 × 多时刻的调色组合会爆炸，且场景的乐趣正在于「另一个世界」。UI 外壳（面板、按钮、抽屉、tooltip）仍全部走 CSS 主题变量，场景像一扇窗。
- **现实天气**（`[factory] weather` + `weather_location`，默认关）：城市名只用于地理编码取经纬度；Open-Meteo 免密钥接口返回 WMO 天气码、气温、`is_day` 与日出日落，服务端缓存 30 分钟，失败沿用上一份可用快照。晴 / 多云 / 阴 / 雾 / 毛毛雨 / 雨 / 雪 / 雷雨分别映射到天空云量、整体明暗、雾层、雨丝、雪花与雷闪；关闭时一次网络请求都不发。
- 调色板常量放 JS，不写进 CSS（现有 `test_frontend_wiring.py` 禁止 CSS 写死色值）。

### 4.4 动效

| 时刻 | 画面 |
|---|---|
| 待机 | 调度厅雷达慢转；传送带纹理滚动；烟囱冒烟；处理机组溅火星；夜间窗光与星点 |
| 天气 | 晴天薄云；多云 / 阴天低垂灰云压暗天空；雨丝、雪片、雾层与雷闪；夜间阴雨遮住星光与月亮 |
| 派工 | 包裹从厅里沿高架传送带滑向目标厂区 |
| 到达 | 机台亮起状态灯，包裹停在机台口 |
| 加工 | 机台上方计时（mm:ss）；包裹在机台口轻晃 |
| 成功 | 成品码上托盘，浮一行「+1 成品」 |
| 失败 | 包裹变红、沿返程带退回调度厅，机台故障灯亮 |
| 空产出 | 空箱灰白，停在带尾 |
| 中断 | 包裹灰化停在原地，标注「上次运行中断」 |

### 4.5 文字与可访问性

- **所有文字用 DOM 覆盖层**，不画进 Canvas：项目名牌、机台名、包裹 tooltip、计时。中文像素字体无法随包分发，DOM 文字在任何 DPI 下都清晰，也天然可选中、可读屏。
- 覆盖层只渲染视口内与悬停目标，最多约 40 个节点；镜头移动时节流更新。
- `prefers-reduced-motion: reduce`：关闭一切位移与粒子，只保留离散状态变化，场景变成一张每分钟刷新的快照。
- 面板、抽屉、工具栏全部可键盘操作；画布本身不承担唯一信息源（左侧面板与底部「全部运行」是等价入口）。

### 4.6 性能

- 单场景最多 60 枚包裹在画，超出折叠为「+N 枚」计数胶囊。
- 一份 rAF 循环；页面不可见、切走视图、窗口失焦时暂停（沿宠物动画的 `document.hidden` 先例）。
- 全量重绘在 10fps 下开销可忽略，不做脏矩形优化；覆盖层 DOM 单独更新。
- Canvas 尺寸用 `getBoundingClientRect() × devicePixelRatio`；界面缩放走 CSS `zoom`，**不要**再乘 `uiScale`。
- 主题切换监听 `<html data-theme>` 变化后重绘；系统深浅切换同样处理。

## 5. 生命周期（一次派工）

```
待发 ──派工──▶ 在途 ──抵达──▶ 加工中 ──┬─成功─▶ 成品
                                      ├─空产出─▶ 空箱
                                      ├─失败──▶ 回炉
                                      └─取消──▶ 撤回（仅编排节点）
```

与真实代码的对应：

| 阶段 | 真实事件 |
|---|---|
| 待发 | `due_cron_tasks()` 命中，或用户点「立即运行」 |
| 派工 | `_cron_pass` → `_run_cron_task`；或 `_pipeline_advance` → `_run_pipeline_node` |
| 加工中 | `automation_runs` 插入 `running`，发 `factory_run(phase=started)` |
| 结束 | `run_cron_task_core` 收尾 / `_run_pipeline_node` 写终态，更新行并 `factory_run(phase=finished)` |
| 中断 | 应用启动时把残留 `running` 统一置 `interrupted`（仿 `reset_interrupted_pipelines`） |

- 动画是表现层：包裹的「在途」是纯装饰，运行早已开始。若运行在包裹走到机台前就结束，包裹直接落定并进终态，不补播无意义的动画。
- 计时的唯一事实来源是 `started_at`，前端本地每秒推算；**不依赖进度事件**（现状 cron / 节点运行没有流式事件进前端）。
- 成品链路：cron 运行 → 新建会话（`sessions`）；编排节点 → `session_id` + `.skysheep/pipeline-results/node-<id>.md`。抽屉里的「打开会话 / 打开产出」直接复用既有入口。

## 6. 调度模型（总厂调度）

### 6.1 能做

- 看全部项目的厂区、产线、工位、在途包裹、今日成品。
- 给任意项目的工位「立即运行」：复用 `_run_cron_task`，执行上下文由目标项目决定（`_cron_execution_context` 已支持按任务所属项目解析工作目录、白名单与系统提示词）。与现有 `cron.run_now` 同口径用 `force=True`：**停工的产线仍可手动跑一次**（停工只拦定时派工），但同一工位在跑时返回 already_running。
- 任意产线「暂停 / 启用」：等价于改 `cron_tasks.enabled`。
- 给指定厂区新建一条**轻量定时产线**：名称、提示词、周期（interval / daily / weekly）、预授权工具。等价于 `store.add_cron_task(project_id, ...)`，只是把「目标项目」从当前项目改为显式指定。
- 点开包裹看详情，跳转会话或产出文件。
- **叫停**任意一条在跑的产线（只取消这一轮）：启用状态与排期不变，落 `cancelled` 终态，不算失败、不进「需留意」。实现上把 `_cron_running` 从 id 集合改成 `id → asyncio.Task` 的登记表，只取消 `spawn_bg` 建出来的后台运行——取消一个正在等回执的请求任务会连带掐掉 WS 回执。
- **看工序**：无头运行原本把事件流整个丢掉，现在只把「当前工具 + 已执行步数」压成 1 次/秒的进度事件，显示在机台、监控面板与抽屉里；超过 30 秒没有新事件即视为无（不显示过期工具名）。
- **看体检与成本**：抽屉里给出近 7 天成功率 / 平均与 P95 / 最慢耗时 / 连续失败次数 / 最近 20 次状态色条，以及本次运行的 token 用量；顶部计数条多一格「今日 token」。
- **消化「需留意」**：按产线标记「知道了」（`factory.ack`，只记时间戳不删历史），更晚的失败会重新浮上来；停工与孤儿是结构性问题，修好即消失，不给这个按钮。

### 6.2 不做（一期）

- 不在工厂里编辑产线内容、管理预授权工具、删除任务——这些仍回自动化页（避免在观战窗里做破坏性配置）。
- 编排（装配线）的叫停仍回自动化页：工厂的「叫停」只针对定时任务（节点取消要处理依赖级联与自动重试，语义不同，不混进观战窗）。
- 不做跨项目供货线（项目 A 的产出自动喂给项目 B）：列三期候选，不在一二期。

### 6.3 与调度循环的关系

- 不改扫描范围：`due_cron_tasks()` 与 `list_pipelines()` 本来就是全项目口径，工厂只是第一次把它们**展示**出来。
- 不改执行上下文：每个任务仍按自己所属项目运行，权限门、白名单、检查点归属不变。
- 唯一新增的调度语义是「显式指定目标项目地新建一条定时产线」，它写的是普通 `cron_tasks` 行，之后完全由现有循环接管。

## 7. 权限与安全

1. **本机专属**：工厂全部 WS 方法 `local_only=True`，与归档管理同一口径（跨项目枚举面不对远程开放）。远程 / 手机连接打开工厂只显示「工厂仅在本机可用」。
2. **派工不放松权限**：工厂只决定「哪个已登记的任务运行」，不注入命令、不改白名单。运行仍走目标项目的 `HeadlessGate`，预授权工具名单照旧 fail-closed。
3. **新建产线不是提权**：`factory.line_add` 写入的是普通定时任务行，提示词是纯文本、永不作为命令执行；预授权工具仍需用户在表单里显式勾选，且沿用现有校验。
4. **演示模式零副作用**：没有真实产线时播放的「样板厂」数据只在内存，永不写库、永不触发运行，界面上明确标注。
5. **重复派工去重**：同一工位运行期间重复点击只派一次，复用 `_cron_running` 去重；完成后可再次派工；跨项目派工同样受此约束。
6. **孤儿任务不掩盖**：项目行或目录丢失时按 fail-closed 拒绝派工，不回退到当前项目运行。定时扫描记录 `error/path` 并重排下次时间；工厂显示孤儿或停工问题。`orphan` 是展示问题类型，不作为运行账本状态写入。
7. **出网只在用户显式开启天气后发生**：城市名交给 Open-Meteo 地理编码、坐标交给天气接口，免密钥、30 分钟缓存、不做 IP 定位；关闭 `[factory] weather` 时一次请求都不发。

## 8. 事件与数据

### 8.1 新表 `automation_runs`

现有表只保存每个任务的**最后一次**运行（`cron_tasks.last_run_at/last_status/last_result`），没有历史、没有耗时（`duration` 算了但只用于渠道推送）。工厂需要「运行」这一实体，因此新增一张表——这也是顺带补上的既有缺口。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 运行编号，也是包裹编号 |
| `kind` | TEXT | `cron` / `pipeline_node` |
| `task_id` | INTEGER | cron 任务 id 或节点 id |
| `pipeline_id` | INTEGER NULL | 仅节点运行 |
| `project_id` | INTEGER | 触发时解析出的归属项目（冗余，便于聚合） |
| `session_id` | TEXT NULL | 本次运行产生的会话 |
| `trigger` | TEXT | 自动调度 `schedule` / 用户明确重跑 `manual`（`link` 预留）；编排自动来源显示「编排自动推进」 |
| `status` | TEXT | `running` / `done` / `empty` / `error` / `interrupted` / `skipped` / `cancelled` |
| `started_at` | REAL | 开始时间 |
| `finished_at` | REAL NULL | 结束时间 |
| `duration_s` | REAL NULL | 耗时 |
| `result_excerpt` | TEXT | 结果摘要，≤200 字（沿 `run_cron_task_core` 的现有截断口径） |
| `error` | TEXT | 错误摘要，≤300 字 |
| `in_tokens` / `out_tokens` / `cached_tokens` | INTEGER | 本次运行的 token 用量（收尾时按「会话 + 本次时间窗」从 `usage_log` 汇总，查不到写 0） |
| `denied_count` | INTEGER | 本轮被无人值守门控拒绝的工具次数 |
| `denied_tools` | TEXT | 被拦工具名 → 次数的 JSON 快照（前 8 项），用于提示该补哪些预授权工具 |
| `error_kind` | TEXT | 失败归因：`permission` / `model` / `path` / `budget` / `timeout` / `unknown` |
| `outcome` / `outcome_source` | TEXT | 做成判定（`ok` / `partial` / `failed`，空 = 无结论）与来源（`auto` / `user`） |

索引：`(project_id, started_at DESC)`、`(task_id, started_at DESC)`、`(status)`。
写入点：`run_cron_task_core` 首尾各一次（被叫停时走取消分支写 `cancelled`）；`_run_pipeline_node` 首尾各一次；`_cron_pass` 发现任务仍在跑时记一条 `skipped`——同一「到点批次」只记一次（按 `task_id + next_run_at` 在内存去重，否则长跑期间每 20 秒就会堆一行）；启动时 `mark_interrupted_runs()` 收尾残留 `running`。
保留：默认保留最近 2000 条或 30 天，启动与每 100 次插入时清理一次（`[factory] history_keep` / `history_days`）。

另有一张极小的 `factory_acks`（`line_key` 主键 + `acked_at`）：「需留意」的已处理标记。查「需留意」时按产线比较时间戳——标记之后发生的失败（`started_at` / `last_run_at` / `finished_at` 更晚）照旧浮上来。

### 8.2 事件 `factory_run`

```json
{"kind": "factory_run", "phase": "started", "run": {"id": 42, "kind": "cron", "task_id": 7, "project_id": 2, "session_id": 118, "...": "..."}}
```

- 只在开始 / 结束各发一次，不逐 token、不逐工具。
- **工序进度**是第三种相位：`phase=progress`，`run` 里只有 `{id, kind, task_id, pipeline_id, progress: {tool, steps, at}}`，1 次/秒节流，不带名字与结果摘要。
- **顶层绝不能带 `session_id`**：前端事件路由会把任何带顶层 `session_id` 的事件当成聊天事件，自动开标签页（`static/app.js` 的通用路由分支）。会话 id 只能嵌在 `run` 里。
- 产线 / 机台的配置状态继续复用 `cron_updated` / `pipeline_updated` 快照，不新增重复事件；前端收到这两个事件后做 200ms 防抖的整份 `factory.state` 重拉（逐字段增量同步迟早和服务端对不上，而一次重拉只是几条索引查询）。

### 8.3 WS 方法

| 方法 | 参数 | 返回 / 行为 |
|---|---|---|
| `factory.state` | `{}` | 项目列表（含 `root_ok`）、产线 / 工位（含 `health` 体检）、在途运行、五个计数（含 `tokens_today`）、需留意、`live` 快照、配置；store 层聚合，不在前端拼全量 |
| `factory.runs` | `kind? / task_id? / pipeline_id? / project_id? / status? / view? / limit / offset` | 运行历史分页；view 为 all / done_today / tokens_today，由服务端按本地零点计算 |
| `factory.live` | `{}` | 只读 RunCenter 内存：在跑的对话轮 / 子代理（含 `stale`）；工厂可见时前端每 12 秒轮询 |
| `factory.weather` | `force?` | 现实天气快照：城市地理编码 + 当前天气 / 昼夜 / 日出日落；30 分钟缓存，失败沿用上次数据；未开启时 `enabled=false` |
| `factory.run_now` | `task_id` | 立即派工；**后台起跑、请求立刻回执**（句柄留在在跑登记表里供叫停）；目标项目目录不可用则报错；已在跑返回 `started=false` |
| `factory.cancel` | `task_id` | 叫停这一轮；没有可取消的句柄时返回 `cancelled=false` + 中文说明，不假装成功 |
| `factory.ack` | `line_key` 或 `line_keys[]` | 标记「需留意」已处理，返回 `acked_at` |
| `factory.toggle` | `task_id, enabled` | 暂停 / 启用产线 |
| `factory.line_add` | `project_id, name, prompt, schedule_type, interval_minutes?, time_of_day?, weekday?, allowed_tools` | 新建轻量定时产线 |
| `factory.save` | 配置键 | 保存 `[factory]` 配置 |
| `factory.run_mark` | `run_id, outcome` | 非运行中记录可判 ok / failed / 空串撤销 |

全部 `local_only=True`；参数只接受 id，不接受路径。当前共十一个方法（`state / runs / live / weather / run_now / cancel / ack / toggle / line_add / save / run_mark`）。

### 8.4 前端接线

- 新模块 `static/app-factory.js`，在 `index.html` 尾部、`app.js` 之后加载（只在首开时拉数据，仿 `app-tools.js`）。
- `app.js` 的 `handleEvent` 加一个分支：`factory_run` 且工厂视图可见时增量更新场景，否则只更新内存态。
- 工厂视图打开时拉一次 `factory.state`；运行中的计时由本地每秒推算，不轮询。
- 新增静态文件要同步 `server/app.py` 的 `_no_store_static` 白名单与 `static/sw.js` 的 `SHELL_URLS` / `SW_VERSION`。
- 第三视图采用互斥的 `settingsOpen / factoryOpen`，统一 `pageViewOpen()` 守卫，未使用早期计划的 viewMode 枚举。
- 六格计数均支持点击、Enter / Space。运行中打开状态预筛选；排队同时列定时等待明细与编排 ready 工位（截断有提示）；今日做成按 finished_at 与做成口径，今日 token 按 started_at 与输入 + 输出；两者均用服务端本地零点。
- 有拦截的问题可「去处理」；定时任务进入所属项目的自动化页，编排进入所属项目详情。编排详情可定位运行工位，但不提供节点授权编辑表单。
- 手动重跑来源按节点一次性登记，等待依赖、额度或会话忙时保留；自动重试和迭代下一轮回到自动来源。该登记在内存中，重启前尚未执行的手动请求来源会回落为自动。

## 9. 存储与配置

- 数据全部在 `~/.skysheep/skysheep.db`，不新增项目目录内文件。
- `config.toml` 新增 `[factory]`：

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关闭后隐藏左侧导航入口 |
| `demo` | `true` | 没有真实产线时播放「样板厂」 |
| `ambient` | `true` | 昼夜天色（按本机时间；开天气时按当地日出日落） |
| `weather` | `false` | 现实天气（默认关；开启后需配合 `weather_location`） |
| `weather_location` | `""` | 天气城市名（只用于地理编码取坐标；空 = 只用本机时间判断昼夜） |
| `history_keep` | `2000` | 运行历史保留条数 |

## 14. 开放问题与非目标

**开放问题（实施前需定）：**

1. **厂区很多时怎么取舍**：内环优先给最近活跃的厂区，还是严格按侧栏顺序？本设计取「严格按侧栏顺序，新项目追加」，确定性优先；若实际观感拥挤，三期再加「活跃优先」。
2. **装配线的工位上限**：一条编排最多画几个工位？建议 6 个 + `+N`，超出部分只在抽屉里列出。
3. **删除的任务是否保留运行历史**：建议保留（历史是事实），抽屉里标「已删除」，不因删任务清账。
4. **暂停的产线是否画机台**：建议画（挂停工牌），否则用户会以为任务丢了。
5. **天气源与隐私**：已定：Open-Meteo 免密钥接口；用户填城市名换经纬度，上传的只有城市名与坐标，不做 IP 定位、不需要 API Key；默认关，30 分钟缓存。
6. **像素调色板是否允许用户选**：一期固定昼夜两套，不开放自定义。

**非目标（当前不做）：**

- 场景旋转 / 真 3D / 自由建造。
- 音效与背景音乐。
- 在工厂里编辑或删除任务、管理预授权工具。
- 跨项目供货线（三期候选，不属于「总厂调度」）。
- 手机 / 远程观战（工厂是本机桌面能力）。
- 多用户共享厂区。

## 15. 三期增补（2026-10-22）：判定可信、兜底与视野

二期能看到「在跑什么」，但三处口径不可信——「停工」只是展示态、「运行中」可能永远不结束、
成功率只代表「模型说过话」。这一节把它们定死。

### 15.1 两个维度：跑完 ≠ 做成

- `status` 回答「跑完了没有」：`done / empty / error / interrupted / skipped / cancelled`；
- `outcome` 回答「做成了没有」：`ok / partial / failed`，空串 = 还没有结论。
  - 自动：`done` 且 `denied_count == 0` → `ok`；`done` 但有被拦 → `partial`；
    `empty` / `error` → `failed`；
  - 人工：运行详情里「这轮算过 / 不算」，落 `outcome_source=user`，优先于自动判定，
    可撤销（撤销后回到自动口径）。
- 成功率 = `ok` 次数 / 真尝试次数。**`partial` 不计入分子**：工具被拦、Agent 绕开写一段
  总结的情况以前算成功，这是成功率没有决策价值的原因。
- `denied_count` 来自 `permission_resolved(decision=deny)` 的计数，`denied_tools` 另存工具名与次数；
  无人值守门控是静默拒绝，这是它唯一会落下来的痕迹；机台标签与进度行上也会带「被拦 N」。
  `partial` 与自动判负的 `empty` 都会进入「需留意」，面板与状态色条也能区分——不能只把
  成功率改对，却让最常见的「预授权没勾全」在观战面上继续显示为绿。
- 定时任务与装配线节点走同一口径：两者都在 `make_progress_emit` 里数被拦工具，收尾写
  `denied_count` / `denied_tools` / `outcome`；装配线连续失败也进入聚合告警。
- `error_kind` 把错误摘要归一成 5 类：`permission` / `model` / `path` / `budget` / `timeout`
  （另有 `unknown`）。目的是让抽屉说「权限被拒」而不是甩一段 400 响应。

### 15.2 停工是执行口径，不是展示口径

`due_cron_tasks()` 只看 `enabled` 与 `next_run_at`，`_cron_execution_context` 在目录缺失时
会回退到当前打开的项目。两条叠起来的后果是：工厂挂着「停工」牌，任务照跑，还把 A 项目的
prompt 跑进 B 项目目录。现在派工前在扫描循环里校验一次项目目录：不可用则不派工，记一条
`error`（`error_kind=path`）并按 `compute_next_run` 重排下一轮（不重排就会每 20 秒刷一条错误）。
`_execute_cron_turn` 同样 fail closed，拦住「自动化页立即运行」与「系统计划任务」两条入口。

### 15.3 兜底

- **硬超时**：`run_timeout_minutes`（默认 60，`0` = 不限）。超时收尾为 `error` +
  `error_kind=timeout` 并释放 `_cron_running`——否则一条挂住的运行会永远「运行中」。
- **并发闸**：`max_parallel_runs`（默认 3，与编排节点同口径）。扫描按 `next_run_at` 升序接
  任务，额度用完就 `break`，剩下的保持 due 状态等下一轮（20 秒）。「排队」= 定时等待 +
  编排里 `ready` 的节点数，因此是真实数字。
- **聚合告警**：连续失败 ≥ `alert_after_failures`（默认 3）且该产线当天未告警过 → 桌面通知，
  开了 `notify_channel` 时再推渠道。`factory_alerts` 按 `(line_key, day)` 去重，每天每条线
  最多一条（逐次推送会很快被静音，反而失去意义）。定时任务与装配线共用同一阈值；装配线
  只补桌面聚合通知，避免和既有逐节点渠道推送重复。

### 15.4 视野：四类 Agent 活动

`factory.state` 新增 `live`：`core/runs.py` 的 RunCenter 里在跑的对话轮（`turn`）与后台
子代理（`subagent`），只读、最多 20 条，`stale`（超过 5 分钟没有任何更新）供前端标
「疑似卡住」。工厂可见时前端每 12 秒调一次 `factory.live`（只读内存、不查库），stale 在
前端按 `updated_at` 本地推算——轮询间隔内也要能自己变红。工厂的「叫停」仍只作用于
定时任务——对话轮的中止在会话里做，语义不同，不共用一个按钮。

### 15.5 操作闭环

- 「去编辑」：切到该厂区、打开右侧自动化标签、把任务行滚进视野并高亮 2 秒
  （`app.js` 的 `openAutomationFor(projectId, taskId)`）；工厂里仍然**不直接编辑**任务，
  编辑面留在自动化页（见 §14 非目标）。
- 「打开产出」：编排节点的全文在 `<项目>/.skysheep/pipeline-results/node-<id>.md`，路径由
  后端在 `run.result_path` 给出；只有文件真实存在时才显示按钮，前端走既有文件预览打开。
- 「全部运行」：状态 / 厂区筛选 + 30 条一页的分页（后端 `factory.runs` 一直支持
  `status` / `project_id` / `offset`）；每次打开都从「全部」开始，避免下拉框与查询条件错位。
- 「需留意」逐条显示「厂区 · 产线：问题」，点一行直接打开对应产线。
- 聚焦档：点厂区头把镜头推进到该厂区（Esc / 工具栏「全景」回全景）。机台名与计时原本因为
  「zoom ≥ 全景 × 1.15」这个恒假条件永远不显示——聚焦档让这个条件真正成立。
