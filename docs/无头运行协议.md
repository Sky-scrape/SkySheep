# 无头运行协议（`skysheep run`）

`skysheep run` 是引擎的一次性非交互入口：不启动界面，跑完一个任务就退出，消息照常落库可审计。
`--output stream` 把 Agent 运行全程的统一事件流（`engine/src/skysheep/events.py` 的 `AgentEvent`）
逐行以 NDJSON 输出——CLI、桌面 GUI、WebSocket 前端消费的是同一套事件，本协议是它在
脚本、CI 与外部程序侧的直连形态。

## 参数

| 参数 | 说明 |
|---|---|
| `prompt`（位置参数） | 任务描述 |
| `-d, --directory` | 工作目录（默认当前目录；不存在直接以退出码 2 结束） |
| `-p, --provider` | config.toml 里的 provider 名（缺省用 `default`） |
| `--allow-tool` | 预授权工具名单，逗号分隔（如 `write_file,edit_file,run_command`）；缺省只放行只读操作 |
| `--output` | `text`（默认，只打印最终回答）/ `json`（结束后输出一个完整结构化结果）/ `stream`（NDJSON 事件流，本文档） |
| `--max-iterations` | 最大工具调用轮数（缺省取 config.toml 的 `max_iterations`） |
| `--trust-project` | 信任项目自带的 `.skysheep/` 配置（启用其 mcp.json 与项目级技能）；无人值守默认不启用 |

## stream 协议

- 每行一个 JSON 对象（NDJSON），UTF-8 编码，写出即冲刷——消费方逐行读即可实时呈现。
- 事件行是引擎事件对象的完整序列化（与 WS 层同一批 pydantic 模型 `model_dump` 的产物）：
  `kind` 是判别字段，`ts` 是事件产生的 Unix 时间戳（秒）。
  **字段定义的唯一事实来源是 `engine/src/skysheep/events.py`**，本文只给索引。
- 末行固定为 `kind: "result"` 的汇总行，之后进程退出。

### 事件行索引

| 分组 | kind | 说明 |
|---|---|---|
| 生命周期 | `turn_started` / `turn_finished` | 每次模型调用开始/结束；`turn_finished` 携带 stop_reason、迭代数、耗时与工具调用聚合 |
| 流式增量 | `text_delta` / `thinking_delta` | 正文与思考过程的流式文本增量，逐 delta 一行 |
| 消息定稿 | `assistant_message` | 每次迭代的完整助手消息（含 tool_use），与落库历史一致 |
| 工具 | `tool_call_started` / `tool_call_finished` | 工具执行起止；finished 携带结果预览、unified diff（写文件类）、`is_error`、耗时 |
| 权限 | `permission_request` / `permission_resolved` | 无人值守下不会挂起等待：门控立即裁决，被拒操作同样在事件流上留下 request + `resolved(deny)` 的痕迹 |
| 过程 | `usage` / `notice` / `error` / `compaction` / `todo_updated` / `task_estimate` | token 用量、非致命提示、错误、上下文压缩、任务清单变化、耗时预估 |
| 多模型协作 | `roundtable_*` / `team_*` / `adversarial_*` | 圆桌、团队、对抗三类协作的对应事件（见 docs/团队模式设计.md、docs/对抗模式设计.md） |

`kind` 集合只增不改语义；消费方按 kind 分发、未知 kind 跳过即可向前兼容。

### 结果行（`kind: "result"`）

| 字段 | 说明 |
|---|---|
| `session_id` | 会话 id（消息已落库，可审计、可在界面里 resume） |
| `provider` / `model` | 实际使用的服务与模型 |
| `stop_reason` | `end_turn` / `max_iterations` / `aborted` |
| `error` | 错误摘要；正常为 null |
| `reply` | 最终回答全文 |
| `usage` | `{input, output}` token 累计 |

完整消息列表（`messages`）不在结果行里——每条消息已由 `assistant_message` 事件承载，
避免同一份数据在一行里重复两次；需要一次性拿全量时用 `--output json`。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | `end_turn` 正常收尾 |
| 1 | 出错、被打断，或 `stop_reason != end_turn`（如达最大工具调用轮数） |
| 2 | 参数或环境错误（目录不存在、provider 不存在、config 读取失败） |

## 无人值守安全语义

写与执行不因无界面而放松：`HeadlessGate` 对只读操作自动放行、`--allow-tool`
名单内的工具自动放行，其余写/高危操作一律自动拒绝（Agent 收到「已拒绝」后继续跑完）。
出站密钥防线与引擎主目录写入守卫先于名单放行——预授权名单不能成为密钥外传的免确认通道。
工作区信任默认不继承项目自带配置，需显式 `--trust-project`。
定时任务入口（`cron run` / `cron-run`）共用同一门控；渠道遥控有对应的无人值守门控，语义一致。

## 定时团队的事件流（`mode="team"`）

定时任务支持团队形态（docs/团队模式设计.md §14）：到点按「团队模板」建队、AI 总管
自动推进闭环，跑完产出《交付说明》。一轮定时团队在引擎内部走的是与交互式团队会话
同一套 `team_*` 事件族（上方事件行索引「多模型协作」行），一次完整闭环的形状：

`team_started`（名册 + 总管形态）→ `team_message`（`from_member: "user"`，cron 任务
的 prompt 作为总管首条指令进频道）→ [`team_message_delta` / `usage` /
`tool_call_started` / `tool_call_finished` / `team_task_updated`]*（总管派工、队员
唤醒回报）→ `team_message`（总管《交付说明》定稿）→ `team_finished`（`status` 取
`done / aborted / rounds_exhausted / budget_exhausted`，`summary` 携带交付说明全文）。

节选（FakeProvider 驱动的真实运行，`ts` 字段略）：

```ndjson
{"kind": "team_started", "roster": [{"index": 0, "name": "队员0", "provider": "fa", "model": "ma", "persona": ""}], "director_mode": "ai", "director_provider": "fa", "director_model": "ma"}
{"kind": "team_message", "seq": 1, "from_member": "user", "to_member": "all", "msg_kind": "ruling", "task_ref": "", "text": "（任务 prompt）"}
{"kind": "team_message_delta", "member_index": -1, "seq": 2, "text": "分工方案…"}
{"kind": "tool_call_started", "tool_call_id": "d1", "name": "team_assign", "input": {"title": "巡检目录", "assignee": "队员0", "type": "exec"}}
{"kind": "team_task_updated", "task_id": "T1", "title": "巡检目录", "assignee": "队员0", "type": "exec", "status": "pending", "redo": 0}
{"kind": "team_message", "seq": 3, "from_member": "director", "to_member": "队员0", "msg_kind": "assign", "task_ref": "T1", "text": "派工 T1「巡检目录」"}
{"kind": "team_task_updated", "task_id": "T1", "status": "in_progress"}
{"kind": "team_message", "seq": 4, "from_member": "队员0", "to_member": "director", "msg_kind": "system", "text": "（队员回报）"}
{"kind": "team_task_updated", "task_id": "T1", "status": "review"}
{"kind": "team_message", "seq": 5, "from_member": "director", "to_member": "all", "msg_kind": "ruling", "text": "《交付说明》：…"}
{"kind": "team_finished", "status": "done", "summary": "《交付说明》：…"}
```

`member_index: -1` 表示 AI 总管；`seq` 是频道消息号（定稿见 `team_message`）。

无人值守下这些事件不外发，消费面是：

- **事件收敛**：定时触发的团队轮不接 `skysheep run --output stream`，也不进 WS 事件
  流——`cron_emit` 把流式 / 权限 / 团队事件收敛成工序进度（1 次/秒，工厂观战窗）。
  `skysheep cron run` 一期对 `mode="team"` 的任务按失败收尾拒绝（报「团队任务暂不支持
  系统计划任务入口」），NDJSON 直连消费一期只覆盖单 Agent 轮。
- **产出四落点**：任务行 `last_result`（≤200 字，终态注记前缀如【轮次耗尽】）；
  交付报告全文 `<项目>/.skysheep/reports/cron-team-<任务id>-<时间戳>.md`（头部带元
  信息块：任务名 / 模板 / 触发方式 / 终态 / 轮次 / 工单板快照 / 用量）；会话消息
  user+assistant 成对落库（可审计）；频道消息全量落 `team_messages` 表，`team.log`
  按 team_id 回放（team_id 随会话 meta 落库）。
- **可选渠道推送**：任务开了 `notify_channel` 时，终态沿既有定时任务路径向绑定的
  飞书 / 微信 / Webhook 渠道推送摘要（结果摘要 ≤500 字，不出站报告全文）；推送失败
  只记日志，不影响任务结果与收尾。

## 消费示例

bash（配合 jq 做最小渲染）：

```bash
skysheep run "整理这个目录并写一份清单" --output stream --allow-tool write_file \
  | while IFS= read -r line; do
      case "$(printf '%s' "$line" | jq -r .kind)" in
        text_delta)        printf '%s' "$(printf '%s' "$line" | jq -r .text)" ;;
        tool_call_started) echo "→ $(printf '%s' "$line" | jq -r .name)" ;;
        result)            printf '\n完成：%s\n' "$(printf '%s' "$line" | jq -r .reply)" ;;
      esac
    done
```

Python（逐行解析，实时呈现，结束时取退出码）：

```python
import json
import subprocess
import sys

proc = subprocess.Popen(
    ["skysheep", "run", "检查测试是否全绿", "--output", "stream"],
    stdout=subprocess.PIPE, text=True, encoding="utf-8",
)
for line in proc.stdout:
    ev = json.loads(line)
    if ev["kind"] == "text_delta":
        print(ev["text"], end="", flush=True)
    elif ev["kind"] == "result":
        print("\nstop:", ev["stop_reason"], "| reply:", ev["reply"][:80])
sys.exit(proc.wait())
```

## 与 WS 协议的关系

桌面应用与远程访问走 WebSocket（`server/app.py` 的 method 分发 + 事件推送），
事件对象与本协议同源（同一批 pydantic 模型）。WS 的 method 面目前是内部实现、
不对外承诺稳定；外部程序接入引擎优先走本协议。
