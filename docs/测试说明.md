# 测试说明

> 这份文档回答三件事：**怎么跑**、**每一层测什么**、**哪些只能人工验**。
> 改动代码后的执行纪律见文末「提交前纪律」——它是硬规则，不是建议。

## 1. 分层

| 层 | 目录 | 规模（2026-11-04） | 跑法 | 用途 |
|---|---|---:|---|---|
| 单元 / 集成 | `engine/tests/` | 202 个文件，约 3600 条 | `uv run pytest -m "not e2e and not eval"` | 每个模块的内部契约、边界、异常分支 |
| 验收 | `engine/tests/acceptance/` | 43 个函数（40 条进程内 + 3 条真实浏览器） | `uv run pytest -m acceptance` | 用户视角的完整旅程与对外规则 |
| 真实 socket e2e | `engine/tests/test_ws_e2e*.py` 等 | 33 条 | `uv run pytest -m e2e` | 真实握手、分帧、长连接、多客户端 |
| 行为评测 | `engine/evals/` | 30 条 | `uv run pytest -m eval` | Agent 行为回归（事件流 / 工具序列） |
| 真实浏览器 | `tests/acceptance/test_ui_journey.py`、`tests/test_browser_ui.py` | 3 + 5 条 | 见 §2.3 | 点击、确认卡、窄屏、主题 |

**默认行为**：`uv run pytest` 会跑单测 + 验收 + e2e，只排除 `eval`
（pyproject 的 addopts 预置了 `-m "not eval"`）。要连 e2e 一起跳过，写
`-m "not e2e and not eval"`。

## 2. 怎么跑

### 2.1 日常（改完代码必跑）

```bash
cd SkySheep/engine
uv run pytest -m "acceptance and not e2e" -q     # 快速验收，约 30 秒
uv run pytest tests/test_<受影响模块>.py -q        # 受影响模块的单测
uv run ruff check .                                # 提交前 lint
```

改了协议（`server/app.py` / `_dispatch_*.py` / `events.py`）或前端 `static/` 时，再加：

```bash
uv run pytest -m e2e -q                            # 真实 socket
```

### 2.2 全量

```bash
cd SkySheep/engine
uv run pytest -q                                   # 单测 + 验收 + e2e（不含 eval）
uv run pytest -m "not e2e and not eval" -q         # 跳过真实 socket 与评测
uv run pytest -m eval -q                           # 行为评测基线
```

2026-11-04 实测（含验收层）：`-m "not e2e and not eval"` 为
**3629 passed / 14 skipped / 1 failed / 9 分 52 秒**。唯一失败是
`test_mcp.py::test_real_stdio_roundtrip`——MCP 演示服务子进程启动时
`MemoryError`（机器内存压力导致的偶发），隔离重跑通过；与此同批的验收层
40 条全部通过。

### 2.3 真实浏览器（可选）

Playwright 不在默认依赖里（要下载约 150MB Chromium）：

```bash
cd SkySheep/engine
uv sync --group browser
uv run python -m playwright install chromium
uv run pytest tests/acceptance/test_ui_journey.py -q
```

未安装时整组自动跳过（`pytest.importorskip`），不影响日常套件与 CI。

### 2.4 数据隔离

- 根 `tests/conftest.py` 的 autouse fixture 把 `SKYSHEEP_HOME` 指到 `tmp_path`，
  **任何测试都不会读写真实的 `~/.skysheep/`**。
- 模型一律用 `FakeProvider` 脚本回放（`_helpers.make_client` / `make_shared_client`）：
  不联网、不耗额度、结果确定。
- 验收层自己造的数据：临时项目目录、GBK/CRLF 文件、300 个会话、151 轮历史、
  坏 `config.toml`、假 `.skysheep/mcp.json`、慢速 provider（停止/取消用）。
- 真实模型 Key、飞书/微信账号、局域网设备、Windows 计划任务都不在自动化范围内
  （见 §5）。

## 3. 验收层用例清单

文件与编号一一对应；想只跑某一组：`uv run pytest tests/acceptance/test_<文件>.py -q`。

### A. 主流程（`test_flow_main.py`）

| 编号 | 用例 | 断言要点 |
|---|---|---|
| A1 | 首次启动无 Key | `boot` 带可读 `provider_error`；聊天报错指路设置页而非手改配置 |
| A2 | 写文件全流程 | 确认卡带落点与 diff → 允许 → 落盘 → 检查点 → 撤销 → 文件消失 |
| A3 | 拒绝写入 | 不落盘；工具结果标错误；Agent 继续收尾 |
| A4 | 会话闭环 | 改名/置顶/标签/搜索/归档/恢复/导出/删除 + `new_active` |
| A5 | 双项目隔离 | 会话、白名单、检查点不跨项目 |
| A6 | 无头 `run --output stream` | NDJSON、末行 `result`、`stop_reason=end_turn` |

### B. 权限与安全（`test_rules_security.py`）

| 编号 | 用例 | 断言要点 |
|---|---|---|
| B1 | 只读自动放行 | `list_dir` 不弹确认 |
| B2 | 权限三档矩阵 | 安全执行全确认；自动编辑只放行工作区内；完全访问放行普通路径；自动编辑下引擎目录仍确认 |
| B3 | 白名单四类规则 | 前缀/精确/整工具命中、不命中、导出→清空→导入后仍生效 |
| B4 | shell 拼接 | `&&` `;` `\|` `$()` 与解释器 `-c` 都不命中前缀规则 |
| B5 | 删除语义 | 自动编辑档不放行「覆盖目录」的 `move_file` |
| B6 | 引擎数据目录守卫 | 自动编辑 + 整工具白名单也放不开 `config.toml` 写入 |
| B7 | 工作区信任 | 项目自带 `.skysheep` 默认 `pending`，grant 后 `trusted`，revoke 回 `pending` |
| B8 | 远程门禁 | `cron.add`/`project.switch`/`permission.set_mode` 被拒；运行记录不跨会话 |
| B9 | 无人值守门控 | 渠道/无头门控未预授权即拒绝；预授权不越出工作区 |
| B10 | SSRF 与注入 | 私网/环回/映射地址拒绝；外部内容进边界框、注入形态被标记 |

### C. 会话、上下文、回滚（`test_rules_session.py`）

| 编号 | 用例 | 断言要点 |
|---|---|---|
| C1 | 压缩可回溯 | 摘要后原文落 `transcripts/`，库里原文仍可查 |
| C2 | 大会话分页 | 首屏 200 条、向前翻页不重叠不遗漏（302 条消息） |
| C3 | 检查点上限与重启 | 每会话 50 条；重启后仍能撤销 |
| C4 | 检查点归属 | 用 B 的会话身份恢复/对比 A 的检查点被拒 |
| C5 | 备份恢复 | 备份→删会话→恢复，消息回来；自动留安全副本 |

### D. 多模型协作（`test_rules_collab.py`）

| 编号 | 用例 | 断言要点 |
|---|---|---|
| D1 | 同轮互斥 | `team` + `roundtable` 直接拒绝；活动团队期间不能开圆桌 |
| D2 | 团队闭环 | 建队→工单→派工→验收→交付→频道回放；交付后回普通回合 |
| D3 | 对抗四阶段 | 发现/调查/建议/裁判事件齐全；统计与裁决正确 |

### E. 自动化与后台（`test_rules_automation.py`）

| 编号 | 用例 | 断言要点 |
|---|---|---|
| E1 | 定时任务 | 建/列/改/停/删；未预授权写被拒、预授权放行 |
| E2 | 编排 DAG | 并行节点 → 汇总节点拿到上游产出；已完成流水线再启动给指引 |
| E3 | 子代理 | 同步报告可查；任务按会话过滤；终态不可再取消 |
| E4 | 工厂 | 空态可出快照；远程一律拒绝 |

### G. 取消 / 返回 / 重试（`test_cancel_return.py`）

| 编号 | 用例 | 断言要点 |
|---|---|---|
| G1 | 流式中途停止 | 已输出文本保留、`stopped=true`、会话可继续 |
| G2 | 确认卡等待中停止 | 不落盘、补发 `decision=cancelled` |
| G3 | 重复回答确认卡 | 第一次决策生效，后续投递不翻转结果 |
| G4 | 前端掉线 | 未决请求仍在队列；回答后原轮继续跑完并落盘 |
| G5 | 编排叫停 | 运行中节点与下游都进 cancelled |
| G6 | 运行重发 | 中断主轮可拿回原文；已完成/不存在的运行明确拒绝 |

### H. 边界（`test_boundaries.py`）

| 编号 | 用例 | 断言要点 |
|---|---|---|
| H1 | 空数据 | 空会话/搜索/归档/检查点/任务/权限队列都是空集合 |
| H2 | 无项目态 | 文件工具回统一可读提示，不是裸异常 |
| H3 | 数量多 | 300 个空会话只回 50 条；一键清理保留当前会话 |
| H4 | 坏输入 | 二进制帧/非 JSON/非对象/未知方法/params 错型都有回执 |
| H5 | 坏配置 | 解析失败给带路径的 `ConfigError` |
| H6 | 多连接 | 两个客户端的会话与回答不串台 |

### I. 真实浏览器（`test_ui_journey.py`，默认跳过）

| 编号 | 用例 | 断言要点 |
|---|---|---|
| I1 | 骨架与 Enter | 输入/发送存在；Shift+Enter 换行、Enter 发送 |
| I2 | 确认卡与撤销 | 允许 → 文件出现；撤销 → 文件消失 |

## 5. 自动化测不到、需要人工验的

1. **WebView2 桌面壳**：窗口创建、单实例、托盘、窗口几何记忆、DPI、DWM 标题栏、开机自启
2. **安装包**：Inno Setup 编译、安装/卸载/升级、SmartScreen、代码签名
3. **真实模型服务**：各家 API Key、限流、计费、能力探测的真实结果
4. **飞书 / 微信真账号**：扫码登录、长连接、群话题、审批卡
5. **Tailscale / 局域网真机**：跨网络连回、二维码、设备踢出
6. **Windows 计划任务导出**：`schtasks` 真实执行、应用关闭时到点跑
7. **电脑控制**：真实鼠标、键盘、截屏、窗口操作
8. **真实 Chrome CDP**：在外部网页上的浏览器控制
9. **代理 / 自签 CA**：真实网络环境下的出网
10. **自动更新**：下载、静默安装、失败恢复
11. **视觉与手感**：工厂场景、六套主题、动效、字体渲染
12. **长时间稳定性**：连续数小时运行的内存/句柄增长

每条的人工操作步骤与预期结果，按功能文档（README、`docs/团队模式设计.md` 等）执行；
发现问题时用 `设置 · 关于 → 导出诊断包` 留档。

## 6. 测试写不到的地方（已知边界）

- **完全访问档按设计放行引擎数据目录写入**（`SECURITY.md`：这是用户显式选择的
  「一切放行」）。白名单 / 自动编辑 / 无人值守 / 渠道四路才会被主目录守卫拦下。
- **重复 `permission.respond` 回 `delivered=true`**（2026-11-04 评估：不修）。
  对「已投递但尚未收尾」的请求，第二次应答仍会回报投递成功；实际生效的只有
  第一次决策（`Agent.respond_permission` 只 `get` 不 `pop`，G3 断言的是效果幂等）。
  决策正确性不受影响；但前端对 `delivered=false` 的文案是「对应的轮次已停止」，
  单改后端会让第二次应答看到错误提示，真修需同时加
  `reason: already_resolved | turn_stopped` 并分文案，留待权限 UX 优化时一起做。
- **WS 发送层只捕获 `RuntimeError` / `WebSocketDisconnect`**（2026-11-04 实测：生产无影响）。
  进程内 `TestClient` 断开时抛 `anyio.ClosedResourceError`，会中断正在 emit 的回合，
  所以 G4 改走引擎层验证；真实 uvicorn 不会抛——连接关闭后 `closed_event` 已置位，
  `asgi_send` 直接丢弃发送（`uvicorn/protocols/websockets/websockets_impl.py:321`）。
  真实 socket 拔线实测：关掉客户端后换连接回答权限，文件照常落盘，
  库里 `user → assistant(tool_use) → tool → assistant` 四条消息完整。
- **真实双屏**：本机只有一块屏，接力模式的主副屏物理验收做不了。

## 7. 提交前纪律（硬规则）

**每次改完代码都要跑测试，并在回复里写明结果。** 最低要求：

1. `uv run pytest -m "acceptance and not e2e" -q`（快速验收）
2. 受影响模块的测试文件
3. `uv run ruff check .`

涉及协议 / 前端再加 `uv run pytest -m e2e -q`；发版前跑全量 `uv run pytest -q`。

回复里必须包含四项：

- 执行了什么命令；
- 通过 / 失败 / 跳过各多少；
- 失败项的名字与原因（没有就写「无」）；
- 因环境缺席而跳过的项（如 Playwright 未安装）单独列出。

不允许只写「测试通过」而不给数字；也不允许跳过失败项只报通过项。
