# 版本支持与更新渠道

> 更新可信度落地的用户侧说明：平台支持范围、渠道怎么选、更新前后系统各做什么、旧版本还收不收修复。
> 发版纪律（版本号一致、校验附件、不 --clobber）见 `docs/发布清单.md`；SmartScreen
> 拦截的放行步骤见 `docs/smartscreen-说明.md`。

## 版本支持策略

- **只支持最新发布版**。发现问题的第一响应永远是「升级到最新版」，不为旧版本出补丁。
- 例外：新版本发布后 14 天内，如果最新版本身有严重回归，会以补丁版本（如 2.6.1）修复，
  而不是回滚发布。
- 版本号遵循三段式 semver（`x.y.z`）：z 位是修复、y 位是功能、x 位是破坏性变更；
  预发布版本带后缀（如 `2.7.0-beta1`），只推给测试渠道。
- 应用内更新的版本比较遵循 semver 预发布规则：正式版新于一切预发布
  （`2.7.0` > `2.7.0-beta1`），预发布之间按后缀逐标识符比较——beta 用户能正常收到
  「转正」推送。

## 平台支持

**Windows 是唯一受支持平台**（10 / 11 x64），这不是「暂时优先」而是当前的产品边界：

- 安装包、桌面壳（pywebview / WebView2）、单实例互斥、窗口几何记忆与 DWM 标题栏主题化都是 Windows 实现；
- 安全模型依赖 Windows 设施：凭据经 DPAPI 按账户加密、受限令牌与低完整性级别沙箱、`taskkill` 进程树回收、`schtasks` 定时导出；
- 系统集成（开机自启走 HKCU Run、系统打开/定位文件、系统计划任务）都只对接 Windows。

macOS / Linux 上的 `--browser` 模式可以跑起引擎与网页界面，供开发者在本机试用，但不在支持承诺内：不做安装包、不保证桌面壳与系统集成能力、不为这些平台维护第二套安全模型。

跨平台支持要等 **Windows 桌面体验达到稳定标准后**再单独评估。在那之前不为跨平台过早抽象安全模型、窗口管理与安装流程——过早抽象会把 Windows 上已经打磨好的行为拉回共同下限。

## 更新渠道（设置 · 关于）

| 渠道 | 更新源 | 收到什么 | 适合谁 |
|---|---|---|---|
| 稳定版（默认） | `releases/latest`（GitHub 官方页面跳转） | 只收正式版 | 绝大多数用户 |
| 测试版 | `releases.atom` 订阅 | 正式版 + 预发布（beta/rc），比稳定版早 | 愿意反馈问题的尝鲜用户 |

两个渠道的检查请求都不走 `api.github.com`（匿名限流对共享出口不友好），失败静默、
不影响使用。渠道偏好保存在 `ui.json`（`update_channel`），切换后立即按新渠道重查一次。

**更新源是固定的**：两个 URL 硬编码在 `core/uptodate.py`，不提供配置项。这不是
疏忽——「改配置指向别处」正是供应链投毒最省事的入口；宁可不提供这个灵活性。
版本号之外的一切（tag 合法性、安装包文件名）都按发布约定机械校验，对不上就拒绝更新。

## 更新链路做了哪些校验（按顺序）

1. **版本号字符白名单**：更新源返回的 tag 只允许字母数字与 `. + _ -`，长度封顶，
   防命令行/路径注入；
2. **体积上限**（300 MB）与 **MZ 头**：下载中途断流或被换成别的东西，直接丢弃；
3. **SHA-256 校验**：必须校，发布方未提供同名 `.sha256` 附件（或拉取失败）时
   **拒绝自动安装**，提示到 Releases 手动下载并自行核对。旧行为是「有则必校、
   无则退回 MZ 头 + 体积上限」——那两道只能防半截文件，不能证明内容未被替换，
   所以改为 fail closed；
4. **代码签名**（发布侧，可选）：配置了证书的环境里，打包产物与安装包由
   `release.py` 自动签名（SHA-256 摘要 + RFC 3161 时间戳）并回验，签名失败中止发布；
   未配置则自动跳过并提示。

**信任边界（请知悉）**：校验和与安装包来自同一个 Release 目录，如果发布账号被
攻破、二者被同时替换，单凭 SHA-256 不能发现。SHA-256 挡的是传输损坏与单侧篡改，
**不能证明发布者身份**。客户端目前尚未验证 Authenticode 发布者证书；正式发布
允许未签名（安装包会触发 SmartScreen 拦截，见 `docs/smartscreen-说明.md`）。
如果你需要更高保证，请自行核对签名指纹或从可信渠道获取安装包。

更新提示与「下载完成」状态都会如实标注校验结果（`verified` 字段），未核对过的包
界面上会明确警示，不会默认当它干净。

## 更新前后系统各做什么

- **更新前**：点「退出并安装」时，先把 `config.toml`、`mcp.json`、`ui.json` 和会话库
  （走 SQLite backup API，含 WAL 未落盘页）备份到
  `~/.skysheep/backups/preupdate-<版本>-<时间>/`，滚动保留最近 3 份；备份**失败项**
  会记入「更新中」标记，失败提示中如实列出（不再笼统说「已备份」）。随后写下
  「更新中」标记（`~/.skysheep/update-pending.json`，原子写）。
- **更新中**：安装器静默运行，过程与退出码记录在 `~/.skysheep/logs/update-setup.log`。
- **更新后**：新版本首次启动时对账标记——目标版本与当前版本一致就清标记并提示
  「更新完成」；不一致（UAC 被取消、互斥体没让位、磁盘满等）则在设置 · 关于亮出
  「上次更新未完成」现场（目标版本、备份目录、日志位置、未备份项），直到用户点
  「知道了」。数据备份目录始终保留，可手动回退配置与会话库。
- **没有自动回滚**：更新失败只做到「可发现、有备份、可手动恢复」，**不自动回退
  程序版本或用户数据**。请按失败提示里的备份目录与日志手动处理。

## 源码版

源码运行的更新方式是 `git pull`（应用内更新会明确拒绝源码版静默装安装包）。
`main` 分支始终可用；预发布对应仓库里的 `v*-*` tag，自行 checkout 即可体验。
