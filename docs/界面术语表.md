# 界面术语表

> 同一概念必须只有一个叫法。新增界面文案、写文档、写帮助时**优先从本表取词**；
> 要改叫法先改这张表，再全局替换（含中英 README 与落地页）。
> 背景：权限体系曾同时存在「安全执行/自动编辑/完全访问」「允许一次/总是允许」「白名单」
> 三套叫法互不指引；「任务」曾同时有五个名词（2.1.0 收敛为两项，2026-10-10 进一步把
> 分段按钮收敛为短名：子代理 / 步骤 / 事项 / 定时 / 编排）。

## 权限与安全

| 术语 | 唯一含义 | 出现位置 |
|---|---|---|
| **权限三档**：安全执行 / 自动编辑 / 完全访问 | 引擎级安全档位，输入区盾牌按钮循环切换，对所有会话一致 | 输入区按钮、设置 · 提示文案 |
| **允许一次** | 放行当前这一次操作，不记忆 | 权限确认条 |
| **确认卡固定字段** | 权限确认卡上的三格元信息：发起方（谁触发的，主会话不显行）/ 范围（影响面：工作目录内外的路径、引擎数据目录、本机全局、公网）/ 可撤销性（进检查点可「撤销本轮改动」恢复，命令与电脑控制类如实标不可回滚）；由引擎随权限请求下发，前端不自行推断 | 权限确认条 |
| **总是允许（本项目）** | 把这条操作规则存入本项目白名单，以后同类操作不再询问 | 权限确认条 |
| **本项目白名单** | 「总是允许（本项目）」保存的规则的**管理入口**，在 设置 · 高级 · 「本项目」分组（该页唯一跟项目走的卡片）；两处文案必须互相指引 | 设置页、权限条按钮 tooltip |
| **拒绝** | 不执行本次操作 | 权限确认条 |
| **工作区信任** | 项目自带的 `.skysheep/`（MCP/技能）首次使用前需确认 | 设置 · 高级、顶栏横幅 |
| **失效徽章（白名单）** | 「本项目白名单」里 2.3.0 安全收紧后不再命中的历史规则的标记：这类规则留着也不会再放行，可逐条删除清理 | 设置 · 高级 · 本项目白名单；徽章文案是「已失效」，悬停显示原因，摘要行同步提示失效条数 |
| **隔离区** | web_fetch 抓取内容的可选处置模式（引擎侧开关，默认关，暂无界面开关）：开启后抓取正文全文落盘隔离文件，模型只见来源、信任级、摘录与隔离文件路径，要全文须用文件读取（经权限门确认并留痕） | 暂无界面入口；「信任级」文案（已知良好 / 已知可疑 / 未知）出现在结构化日志与隔离区回包的头部来源行，默认边界框头部不带信任级 |
| **Mod（扩展）** | 用户或第三方编写的事件处理扩展（实验性）：有两种运行模式——quickjs 沙箱模式（只能**收紧**安全行为，永不放行）与 Claude 兼容模式（Node.js 无沙箱，可 allow / ask / deny / rewrite）。两种模式由 `[mods_claude]` 配置切换、互斥 | 唯一入口「设置 · Mods 扩展（实验性）」；权限卡上的 Mod 说明、消息流里的 Mod 片段都带 `[Mod·<id>]` 来源前缀 |
| **Claude 兼容模式** | Mod 运行在 Node.js 进程内（无沙箱）的模式：兼容 Claude Code 插件格式（`.claude-plugin/plugin.json`），可返回 allow / ask / deny 决策或改写工具参数；与 quickjs 沙箱模式互斥 | 设置 · Mods 扩展（实验性）；由 `[mods_claude]` 配置启用 |
| **Mod 片段** | Mod 产出的声明式展示元素（状态条 / 徽章 / 进度 / 时间线 / 文本五种固定形状），由固定渲染器呈现；Claude 兼容模式还支持元素树（box / text / button / input / select / image） | 输入区右侧状态托盘、消息流、权限确认卡、对话区顶部（pane）、输入框上方（above_prompt）、模态浮层（dialog）；Mod 不能自由绘制界面 |
| **收紧声明（Mod）** | Mod 清单里的静态收紧表（纯 Python 求值，不依赖 JS）：`deny_tools` 命中即拒绝执行；`require_confirm_tools` 命中即强制逐次确认——白名单、「自动编辑」档、「完全访问」档都压不住它 | 设置 · Mods 扩展 的清单行徽标；权限卡注记「Mods 收紧声明命中」 |

## 迭代与回合（Mods 事件口径）

| 术语 | 唯一含义 | 说明 |
|---|---|---|
| **迭代（iteration）** | 一次模型调用及其工具处理为一个迭代 | Mod 的「迭代开始」事件是**迭代级**：一次用户提交会触发多次（每次模型调用一次），不含消息文本 |
| **回合（turn）** | 从用户提交到最终回答（或停止）的完整过程，可含多个迭代 | Mod 的「回合结束」事件是**回合级**：一次提交至多触发一次 |

## 导航与功能名词

| 术语 | 唯一含义 | 说明 |
|---|---|---|
| **会话 / 对话** | 会话是可保存、切换、归档的实体；对话指消息内容与交流行为 | 实体入口统一叫「新建会话」，不叫「新建对话」 |
| **任务** | 右面板容器标签，内含三个分段：子代理 / 步骤 / 事项（2026-10-10 起分段按钮用短名） | 侧栏与窄栏入口均叫「任务」，不再单独露出「任务清单」「项目任务」 |
| **步骤** | 「任务」标签里的 todo 分段（Agent 拆解的执行步骤） | 分段按钮叫「步骤」；「任务清单」只作引擎/文档概念名，不作界面名词 |
| **事项** | 「任务」标签里与项目绑定的手动待办分段（引擎概念名「项目任务」） | 分段按钮、弹窗、空态与操作提示统一叫「事项」；「项目任务」只作引擎/文档概念名，不作界面名词 |
| **自动化** | 右面板容器标签，内含两个分段：定时 / 编排（2026-10-10 起分段按钮用短名） | 侧栏入口叫「自动化」；「定时任务」「任务编排」只作引擎/文档概念名，出现在说明文字里，不作分段按钮文案 |
| **浏览器自适应** | 右面板「浏览器」页的页面呈现模式：整页缩到面板宽、视口限高一屏并垂直居中（默认开），不出横向滚动；悬停面板时 Ctrl+滚轮步进「页面缩放」（不动全局界面缩放） | 工具栏按钮叫「自适应」，另一档叫「原始」（原始大小，宽页面出横向滚动） |
| **MCP / Skills** | 技能与 MCP 服务的统一管理入口（右面板页签；管理卡片在「设置页 ↔ 右面板」之间共享是既有机制，不要新建第二套管理界面） |
| **能力探测** | 设置 · 模型服务详情页的独立按钮：对流式输出 / 工具调用 / 图片输入 / 思考强度各发一次最小真实调用，回答「这个模型能干什么」；与「测试连接」（只回答能不能对话）严格区分 | 「🧪 能力探测」按钮；结果以芯片展示（✓ 支持 / ✗ 不支持 / — 没测成），并给出一句「适合干什么」的结论；会产生少量真实计费 |
| **测试连接** | 设置 · 模型服务详情页的最小真实调用（1 token 非流式），验证 Key、地址与模型真的可用 | 「🔌 测试连接」按钮；结果含是否在模型列表、上下文窗口，并同步健康灯 |
| **复制诊断** | 把最近一次「测试连接」与「能力探测」结果整理成脱敏纯文本并复制（Key 前缀、Bearer 头、URL token 参数自动打码），可发反馈或留档 | 「📋 复制诊断」按钮；仅在测试或探测过后出现 |
| **场景模板** | 设置 · 技能与工具「技能扩展」分组里的官方场景技能包一览（数据来自引擎打包内清单，逐条标「已安装」、可一键安装进全局技能） | 不是技能广场：无在线检索与远端索引；安装走既有 skills.install 链接流程，统一叫「场景模板」，不叫「模板广场」「技能商店」 |
| **项目记忆** | 当前项目的 AGENTS.md | 区别于「全局记忆」「记忆地图」 |
| **全局记忆** | 跨项目用户记忆（`~/.skysheep/` 下 memory.md） | |
| **记忆地图** | 项目演化的可视化（时间线 + 主题图谱 + 演化摘要） | |
| **圆桌 / 团队 / 对抗 / 接力** | 四种多模型协作方式，配置入口统一在「设置 · 技能与工具」页（侧栏不单列），运行时入口在左侧导航与输入区协作菜单 | 新增协作方式时按此口径：说明卡进技能与工具页，不新开设置子页 |
| **对抗** | 多模型对抗性审查模式：发现 → 调查 → 建议 → 裁判四阶段审查流程，产出终审审查报告（与「圆桌」「团队」并列，协作菜单四选一；docs/对抗模式设计.md）；这里的阶段顺序不叫「接力工作台」 | |
| **发现者 / 调查者 / 建议者 / 裁判** | 对抗的四角色：发现者穷举找问题（宁滥勿缺）、调查者逐条对抗验证（confirmed/refuted/partial）、建议者给修复方案、裁判（当前主模型）出终审报告；同一模型可身兼数角 | |
| **候选问题** | 发现者提出的待验证问题条目（不叫「Bug 清单」）；裁决分 成立 / 已推翻 / 部分成立 / 待定 | |
| **子代理** | Agent 派出的后台分身；「任务」标签的第一分段（按钮短名「子代理」） | 「子代理任务」是完整概念名，按钮只用「子代理」 |
| **团队** | 多模型分工协作模式：总管派工、队员执行、验收交付（与「圆桌」并列） | |
| **接力工作台** | 主屏与副屏交替工作的独立工作台；每轮在各自会话中完整运行 Agent，可使用工具并经过权限确认与检查点保护 | 左侧导航「接力」（右侧看板）；主屏绑定当前会话，副屏使用独立会话；每轮可指定执行屏幕。设置里不单列入口——说明卡在「设置 · 技能与工具」，与圆桌 / 团队 / 对抗并列 |
| **主屏 / 副屏** | 接力工作台里的固定界面位置；主屏对应当前会话，副屏对应接力时打开的独立会话 | 同页分栏呈现，不代表物理双屏；两边任务可分别配置 |
| **交棒** | 当前一轮结束后，将任务交给另一屏幕继续处理 | 接力工作台操作；具体执行屏幕由每轮任务配置决定 |
| **总管** | 团队中唯一的编排角色：拆解、派工、验收、裁定、交付；分「用户总管 / AI 总管」 | |
| **队员** | 团队成员 = provider/model + 成员名 + 一句话人设 | |
| **执行型 / 顾问型** | 工单级类型：执行型带工具干活，顾问型只出意见 | |
| **工单** | 团队内分派的活（不叫「任务」） | |
| **分工方案** | 立约阶段产出：目标重述 + 工单清单 + 协作约定 | |
| **团队频道** | 团队全员共享消息簿（与聊天「渠道」严格区分） | |
| **小会** | 总管就单一争议发起的小范围合议：2~3 名相关队员各表一轮意见，总管收口裁定（复用圆桌） | |
| **交付** | 团队终态：总管产出《交付说明》 | |
| **打回** | 验收不合格退回重做（附理由，redo+1） | |
| **插话** | AI 总管模式下，用户消息照进频道并以最高优先级注入总管下一轮（总管空闲时尽快唤醒） | |
| **接管** | 用户把 AI 总管切回用户总管（在飞总管轮干净取消，工单板与频道保留） | |
| **收队** | 用户立即终止团队并出未尽事项 | |
| **团队模板** | 已保存的成员名单 + 总管形态 + 人设组合，可反复用于建队；存放 `~/.skysheep/teams.json` | 建队浮层「从模板创建」、团队卡「另存为模板」；与「场景模板」（官方技能包一览）是两回事，不要混用 |
| **检查点 / 撤销本轮改动** | 每轮文件改动快照与一键回滚 | 不要写「快照回退」「历史版本」等别称 |
| **运行中心（今日运行）** | 自动化页顶部的当日无人值守总览卡：今日任务成败计数、今日 token 用量与预算剩余、下次调度、日报开关状态，可展开当天执行明细 | 界面卡片标题是「今日运行」；文档里统一写「运行中心（今日运行）」，不要另造「运行总览」「执行中心」等叫法 |
| **运行中心（设置页）** | 设置 · 运行中心：所有 Agent 正在跑与跑过的事（主对话轮、后台子代理任务）的统一列表，含状态、错误、停止、重发/重跑与等待确认分区 | 与「运行中心（今日运行）」同名不同物：一个是设置页的全局运行列表，一个是自动化页的当日无人值守总览卡；写文案时按位置区分，不另造「运行总览」等叫法 |
| **重发 / 重跑** | 运行中心对失败或被重启打断的运行提供的恢复入口：主对话轮叫「重发」（把原文在同会话再发一次），子代理任务叫「重跑」（按原类型与原文重新派生） | 仅失败（`failed`）与中断（`interrupted`）的运行有这两个按钮；已完成的运行不提供（避免写入类任务重复副作用） |
| **服务类型 / 服务名称** | 设置 · 模型服务详情页「基本信息」表单的两个字段标签：前者是协议类型（openai 兼容 / anthropic 原生），后者是配置里的服务标识 | 详情表单不再用「供应商类型 / 供应商名称」；用户层统一叫「模型服务」 |
| **待审候选（记忆沉淀）** | 轮次收尾自动抽出的「值得长期记住的事实/偏好」候选：与既有记忆去重后进待审列表，逐条采纳（写入全局记忆）或忽略，不采纳不动记忆 | 入口在记忆地图面板，有待审才展开；开关叫「轮次自动沉淀」，默认关 |
| **每日运行日报** | 每天到设定时刻，把当天定时任务与任务编排的终态汇总成一条中文日报，经已启用的聊天渠道 / Webhook 推送一次；应用没开着错过时刻，开机后补发当天一份，当天推过一次（含送达失败的尝试）就不再推 | 自动化面板的开关行 + 推送时刻（24 小时制，默认 09:00），开关默认关 |
| **预算告警** | 当日 token 用量越过预算 80% / 100% 两档时，各经已启用且配置齐全的聊天渠道 / Webhook 推一条中文提醒；同档每天最多一条 | 无独立开关：设置 · 高级 设了每日预算 + 启用渠道即生效；「预算护栏」指本应用内的硬拦截，与告警是分工关系，两个词不要混用 |
| **思考强度** | 每会话独立档位（自动 / 低 / 中 / 高），未设置时跟随本会话所用模型的服务配置；主栏顶栏「思考」徽章调当前会话，分屏列徽章调该列会话 | 主栏输入区工具条徽章、分屏列工具条徽章 |

| **存储占用与清理** | 设置 · 关于的卡片：展示数据库/备份/日志体量与各账本表行数，可按保留天数清理或清空单表，并支持「整理数据库（VACUUM）」释放空间 | 数据管理卡下方；「清理」只针对账本类数据（用量记录/团队频道消息/连接来源/项目地图摘要） |
| **完整导出** | 换机迁移包：含会话数据库快照、技能目录与配置（默认打码，可勾选含 API Key）的 zip，存数据目录 `exports/` | 与「导出设置」（仅配置类文件）是两个入口，不要混叫 |
| **导入设置预览** | 导入设置 zip 前的确认步：列出将恢复的文件、大小与「含 Key/令牌」标记 | 设置 · 关于 · 设置导出/导入 |
| **已连接设备** | 当前在线的远程访问连接（IP/来源/连接时间/客户端），可一键断开 | 设置 · 手机控制 / 远程访问卡片；本机窗口不列入 |
| **最近访问** | 成功验令牌的远程访问留痕（与「令牌验证失败」留痕对称） | 同上卡片 |
| **来源标记（技能）** | 技能目录里的 `.source.json`：安装来源类型、网址、时间；界面按参考展示（可被包作者伪造） | 设置 · 技能列表的来源 chip；与「场景模板」的官方来源是两回事 |
| **变更记录（扩展）** | MCP / 技能 / Mod 的安装、更新、删除、启停历史（`audit.jsonl`） | 供回溯「什么时候装了什么」 |

### 工厂（跨项目自动化）

| 术语 | 唯一含义 | 说明 |
|---|---|---|
| **工厂** | 跨项目的自动化观战与派工页，与「对话」「设置」并列的第三顶层视图 | 不新增执行模型：背后仍是现有的定时任务与编排，权限、工作目录与白名单照旧。与「自动化」（右面板，管当前项目的配置与任务行）分工——那边配置，这边观战与派工；与「记忆地图」看过去相对，工厂看此刻；与「接力工作台」靠人交棒相对，工厂由调度循环按点派活。写文案统一叫「工厂」；只有侧栏那个入口按钮例外——它写「**工厂看板**」（与「新建会话」并列的主操作），指的还是这个页面 |
| **厂区** | 工厂场景里的一座项目厂区，与「项目」一一对应 | 快聊与远程连接等哨兵项目不建厂区；项目行或目录缺失时标为孤儿或停工，派工拒绝执行，不回退到当前项目。厂区不是新实体，不能在工厂里新建项目 |
| **产线** | 厂区内的一条自动化：一个定时任务是单机产线，一条编排是多工位装配线 | 界面上说「产线」「装配线」，不说「流水线」——「流水线」是引擎概念（`pipelines` 表与编排）；也不叫「任务」，「任务」是右面板容器词（子代理 / 步骤 / 事项） |
| **工位** | 产线上可以派活的最小单位：定时任务本身，或编排里的一个节点 | 立即运行、暂停与运行历史都以工位为单位；装配线的工位按依赖顺序排开，边是传送带 |
| **包裹** | 一次真实运行：一次定时到点、一次手动派工或一次编排节点执行 | 包裹不叫「任务」；一枚包裹对应运行账本里的一行，带运行编号，可点开看详情。上一轮未结束又到点时不产生新包裹，只记一条「跳过」 |
| **成品** | 一次成功运行的产出：本次运行产生的会话、报告或结果文件 | 成品码在厂区托盘上，点开直达会话或产出文件；空产出落废料筐，不计入成品 |
| **调度厅** | 场景中央的调度枢，对应引擎跨项目的自动化扫描循环（定时扫描与编排推进） | 不是独立功能入口，也不新增调度语义；厅顶「在转 N 件」与实际运行数一致 |
| **派工** | 在工厂页手动触发一次运行（立即运行） | 与团队「派工」（总管给队员分派工单）同名不同物：工厂的派工对着机器，团队的派工对着人。停工的产线仍可手动派工一次；同一工位在跑时重复派工只算一次 |
| **停工** | 产线被暂停，或厂区不可用（项目行 / 目录缺失）而不能自动派活的状态 | 手动可运行已暂停但目录可用的产线；项目行或目录缺失时手动派工同样拒绝；它对应自动化里的「暂停」，不是删除任务。编辑、删除任务仍回自动化页 |
| **回炉** | 运行失败：包裹变红、盖章退回调度厅，厂区故障灯闪烁 | 回炉是失败结果的表现，不是重跑动作；是否重跑由用户在抽屉或自动化页决定，不自动重派 |
| **叫停** | 中止某一轮正在跑的运行，只作用于这一轮 | 不是暂停产线：启用状态与排期都不变，下一轮照原计划继续；已消耗的 token 不退回。落 `cancelled` 终态，不算失败、不进「需留意」，也不拉低成功率 |
| **工序** | 一轮运行此刻正在做的事（当前工具名 + 已执行步数） | 每秒最多更新一次；超过 30 秒没有新事件就当作没有，不显示过期工具名。工序只是观战信息，不改变执行 |
| **产线体检** | 一条产线近 7 天的成功率、平均 / P95 / 最慢耗时、连续失败次数与最近 20 次状态色条 | 成功率分母只算真尝试（排除运行中、跳过与叫停）；耗时样本含失败的尝试。连续失败按 outcome 口径：error / interrupted / empty 与人工判负都算失败，遇到 ok / partial 才清零 |
| **做成** | 一次运行是否产生了可用产出，与「跑完」分开 | `done` 且无被拦 = `ok`；`done` 但有被拦 = `partial`（有拦截）；`empty` / `error` = `failed`。人工可在运行详情里推翻自动判定；「今日做成」按 `ok` 计 |
| **有拦截** | 一轮运行里至少有一次写入 / 执行工具被无人值守门控拒绝 | 状态仍是 `done`，但 outcome 是 `partial`：进入「需留意」，不算今日做成；运行详情列出被拦的具体工具与次数，面板与状态色条用警示色 |
| **现实天气** | 按工厂设置里填写的城市获取的真实天气与日出日落，用来决定场景的云、雨、雪、雾与昼夜 | 默认关；只上传城市名换坐标，不做 IP 定位、不需要 API Key；30 分钟缓存，失败沿用上一份可用数据 |
| **知道了** | 把「需留意」里某条产线的问题标记为已处理 | 只记一个时间戳，不删运行历史；同一产线更晚的失败会重新浮上来。停工与孤儿属于结构性问题，修好即消失，不给「知道了」 |
| **样板厂** | 没有真实产线时播放的演示场景，数据只在内存 | 界面明确标注「样板厂」；永不写库、永不触发真实运行，与真实厂区一眼可分 |
| **名牌** | 厂区与机台上的名称标签，可由底部工具栏整体开关 | 关掉只隐藏文字覆盖层，不影响数据、计数与点击目标 |
