# 窄屏（手机端）巡检

手机端（局域网 / Tailscale 访问、以及把窗口拖窄到 ≤860px）的布局回归检查。
断言只有一条：**视口宽 390px 时，任何一页都不该有元素被推出右缘**——被推出去
通常表现为「按钮看得见、点不到」，比样式难看严重得多。

## 怎么跑

1. 起隔离服务（不碰真实用户数据）：

   ```bash
   SHOT_PORT=8917 SkySheep/engine/.venv/Scripts/python.exe -c "
   import os, sys, runpy
   sys.path.insert(0, 'SkySheep/engine/src')
   os.environ['SHOT_PORT'] = '8917'
   runpy.run_path('.shotenv/serve.py', run_name='__main__')"
   ```

   端口挑一个空闲的（8791 / 8795 常被别的应用占着）；`serve.py` 会注入
   FakeProvider，模型只负责「说话」，工具调用是真执行的。

2. 跑巡检脚本（视口 390×844、`isMobile`、`hasTouch`，headless Chrome）：

   ```bash
   NARROW_URL=http://127.0.0.1:8917/ \
     node .shotenv/narrow-probe.js > .shotenv/narrow-report.json
   ```

   脚本做三件事：逐页量 `document.documentElement.scrollWidth` 与
   `innerWidth`；扫出所有「右缘超出视口」的元素（含选择器、边界坐标、宽度）；
   逐页存图到 `.shotenv/narrow/*.png` 供人眼复核。

3. 看结果：`with-overflow` 应为 0；非 0 时打印出越界元素，按选择器去 `app.css`
   的 `@media (max-width: 860px)` 段补规则。

## 两个坑（都会让脚本「看起来没测到东西」）

- **窄屏下侧栏 / 右面板是平移出视口的覆盖抽屉**：它们天然在视口外，先把
  `#sidebar`、`#right-panel` 子树排除，只在 `body.sidebar-open / right-open`
  时才计入。否则每一页都会报十几个「抽屉越界」的假阳性。
- **不能用 Playwright 的点击进设置页**：`#btn-settings` 在抽屉里，可见性检查
  会判 `outside viewport` 直接超时。脚本改用页面自己的 `openSettings(target)`
  导航（本巡检量的是布局，不测可达性）。

## 2026-10-30 首轮结果

16 个页面（聊天页 + 设置 15 页）在 390×844 下**全部无横向溢出**。查出并修掉两处
真问题（都在设置页，属「看得见点不到」）：

| 页面 | 现象 | 修法 |
|---|---|---|
| 设置 · 子代理 | 列表行右侧「策略下拉 ×2 + 编辑」共约 361px，把整行推出右缘 16px | 窄屏下让行 `flex-wrap`，操作组占满一整行、下拉可伸缩 |
| 设置 · 关于 | `D:\…\config.toml` 这类长路径右端被裁 | `.about .copyable-path` 允许任意处断行（`overflow-wrap: anywhere`） |

复验：同一脚本重跑，16 页 `with-overflow = 0`，截图逐页人工过了一遍
（`.shotenv/narrow/`）。

## 下次改前端后

改完 `static/` 里任何布局相关的 CSS / HTML，跑一遍上面两步即可；脚本无需改动，
新增设置页时在 `STEPS` 里补一行 `["settings-xxx", "xxx"]`（`data-target` 见
`index.html` 的 `#settings-nav`）。
