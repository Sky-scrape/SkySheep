# 远程观战设计（跑道 T4.1/T4.2）

定位：把「Agent 现在在干什么」的只读摘要送到人不在电脑前的地方（飞书/微信/Webhook），
衔接渠道（`channels/`）与工厂/团队状态聚合。**纯呈现**——不做任何遥控写操作、
不开命令执行通道（工厂定位=纯可视化，编排需求走流水线与团队本身）。

## 1. 内容与数据源（全部只读）

摘要文本由纯函数 `compose_spectate_digest(state, teams, now)` 拼装：

- 工厂：`factory_state()` 的 counters（在跑/排队/今日完成/需留意）、各项目产线数、
  `attention` 明细（`project_name · line_name：text`，至多 5 条）；
- 团队：`self._teams` 各队 `snapshot()["team"]` 的名称/成员数/工单张数，常驻标记计数；
- **不含**：对话正文、任务 prompt、预授权名单、绝对路径、任何密钥——摘要里不拼
  任何来自 config 的值。

## 2. 通道与节奏

一期两个 WS 方法（均 `local_only`，仅本机）：

- `spectate.snapshot`：返回 `{digest, generated_at}`，前端/脚本取摘要；
- `spectate.send`：把当前摘要经 `push_text_to_targets(self.channels, …)`（cron 收尾
  同款出站小件）推给全部目标渠道，返回 `{delivered}`；渠道未配置/发送失败静默
  （无目标返回 0，单渠道失败只记日志）。

定时自动推送：一期不做独立循环——推送节奏的无人值守门控与节流（HeadlessGate
口径、频率上限）需要单独评估，列为二期（见 §5）；当前「定时」场景由用户在
自动化页建任务、任务收尾推送本就可达。

## 3. 安全口径

- 两个方法都 `local_only`：摘要含工单名与状态，属本机运营信息，不对远程/token
  设备开放（与工厂六方法全本机同口径）；
- 推送目标沿用渠道纪律：聊天渠道 `allowed_ids` 非空才发、纯出站渠道广播
  （`_cron_push_targets_of` 原样复用，名单为空拒发一切）；
- 单队快照失败不拖垮整份摘要（逐队 try/except 跳过）。

## 5. 开放问题（二期）

- 定时节律的门控与节流（无人值守推送的频率上限、免打扰窗口）；
- 富卡片（P21）与按团队分卡片；
- 频道侧「看板命令」（只读拉取摘要的入站斜杠命令，需过渠道门控评估）。
