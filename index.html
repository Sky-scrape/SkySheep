工厂看板 · v2.6.2 已发布

任务在跑，
工厂也在运转

每个项目一座厂区，每条自动化一条产线。机台亮灯、包裹前进、成品装车，把分散的定时任务与编排，放进一张看得见进度的地图。

结果有迹可查

成功进成品区，失败进返工区。每次运行留下耗时与结果摘要；遇到权限拦截，会标明「有拦截」，方便判断任务是否真的做成。

运行有边界

并发满额自动排队，单次运行有超时上限，连续失败会聚合提醒。需要时在本机手动派工或查看运行记录。

Multi-model

一次任务，三种把多个模型组织起来的方式

三种模式在图形界面里直接开关，不用拼命令行参数。同一轮只能选一种，避免互相打架。

圆桌 —— 一次提问，多个模型共同作答

成员模型并行独立作答，主席（主对话模型）把全部草稿融合成一份最终答案，锋利的批评和稳妥的结论都能留下。

可调的部分

  1. 身份预设：批评者、事实核查员、简洁派、实干者等五种成员角色
  2. 辩论修订：可开启辩论轮，成员互看草稿后再修订一轮；A/B 模式保留各自原始回答
  3. 草稿留存：每份草稿随会话落库，可回看、引用、追问

流程示意

成员 A独立作答 · 批评者
成员 B独立作答 · 事实核查
成员 C独立作答 · 实干者
主席融合成一份最终答案

输出：一份融合结论 + 可回看的全部草稿

雷同草稿会去重、成员使用轻上下文等七项机制用于控制 Token 消耗。

团队 —— 按角色分工，工单板跟进度

把一个大任务拆成若干工单，每个队员有自己的角色、模型和工具范围，在团队频道里汇报、被验收、被打回重做。

两种总管

  1. 用户总管：你每条消息就是一道指令，自己决定派给谁
  2. AI 总管：指定一个模型当总管，自动推进拆解 → 派工 → 收报 → 验收 → 交付；你保留插话、接管、收队三权
  3. 小会：需要几个人碰一下时开一轮圆桌，讨论只在频道里呈现，不打断主线

流程示意

总管拆解任务 · 派单
队员 1认领工单 · 执行
队员 2认领工单 · 执行
总管验收 / 打回 / 改派

输出：可交付成果 + 完整频道记录

防失控上限：全局轮次上限、重复返工超限强制裁定、成员停滞自动移交总管、Token 预算越线强制交付。

对抗 —— 专门找错的审查流水线

不追求答案好看，追求把问题挖出来。四个角色接力，各自只看得到自己该看的那部分，避免互相迁就。

为什么更难被糊弄

  1. 不对称激励：挑出问题的收益高于点头附和，角色设定上就不鼓励和稀泥
  2. 阶段上下文隔离：发现、调查、建议、裁判各自独立，后面的角色不被前面的措辞带偏
  3. 失败隔离降级：某一环失败不会让整条流水线作废，按降级路径给出可用结论

流程示意

发现列出可疑点
调查逐条核实
建议给出改法
裁判裁定哪些成立

输出：成立的问题清单 + 对应修复建议

审查结论可一键转为团队顾问工单，让发现的问题继续进入分工处理。

Safety by default

让 Agent 替你动手，前提是出了事兜得住

安全是默认行为，不需要先配置一轮。

  • 每一步先确认

    只读操作自动放行；写文件（附 diff 预览）与执行命令默认逐次弹卡确认。三档权限模式可调，放宽档仅限本机界面切换。

  • 命令白名单按实际 shell 判定

    按完整词前缀匹配；含 shell 拼接或解释器旗标的命令不命中规则、一律重新确认。规则按项目持久化，设置页可管理。

  • 改动可回滚

    文件改动按轮快照，一键撤销本轮改动，重启后仍可回滚；每会话保留 50 轮，全项目兜底 500 条。

  • 会话本地存储，无遥测

    会话、配置、密钥存于本机，无遥测。网页抓取仅允许公网 http(s)、具备 SSRF 防护；外部网页内容按数据处理，不当作指令执行。

  • 出错了有得救

    会话库自动滚动备份可可视化恢复；项目自带的 MCP 与技能配置需先确认信任；诊断包导出自动打码密钥。

FAQ

几个容易被问到的地方

本地存储，为什么还需要连接模型服务？+

本地存储指的是：会话、配置、密钥、检查点、记忆都存在你自己的电脑上，SkySheep 不设遥测，也不把这些资料收集到自己的服务器。

而当你配置的是云端模型服务时，发出去的那段对话内容自然会经过服务商——这是模型推理本身的要求，和「数据被应用收集」是两回事。要完全不出本机，可以接本机推理服务，SkySheep 会自动检测。

多模型协作会不会很贵、很慢？+

会比单模型贵一些，这是实话。所以三条控制线都在：圆桌有雷同草稿去重、成员用轻上下文等七项机制压 Token；团队有全局轮次上限，Token 预算越线强制交付；成员模型可以各自指定——便宜模型跑成员，强模型当主席或总管。

速度上，圆桌的成员阶段并行作答，团队按工单并发；对抗是四角色接力，本来就是串行换来更彻底的审查。

定时任务需要应用一直开着吗？+

默认是的。定时任务与日程提醒由应用内循环触发，所以关窗时选择「缩到系统托盘」才会继续后台运行；彻底退出期间到点的任务会在下次启动补跑。

如果需要应用完全关闭也照常执行，在任务卡片上点「⊞」导出为 Windows 系统计划任务，到点以无头模式独立跑。

改动可回滚，具体能撤到什么程度？+

文件改动按轮次快照，可以一键撤销本轮的文件改动，重启应用后仍然能回滚。每会话保留 50 轮，全项目兜底 500 条。

注意回滚覆盖的是文件改动，不是整个系统状态——命令执行产生的副作用（比如已经发出去的请求、已经推到群里的消息）不在回滚范围内。这也是为什么执行命令默认要你确认。

支持 macOS 或 Linux 吗？+

SkySheep 是Windows 桌面产品。安装包、桌面壳、凭据加密、Windows 沙箱、窗口与进程管理、计划任务导出都只针对 Windows 打磨。

--browser 模式能在 macOS / Linux 上跑起引擎与网页界面，属于开发者兜底路径，不在支持承诺内。跨平台要等 Windows 桌面体验达到稳定标准后再单独评估。

为什么安装包会触发 SmartScreen 警告？+

因为目前安装包还没有代码签名证书。未签名程序首次下载运行被 SmartScreen 拦截是 Windows 的默认行为，不代表检测到了病毒。

点「更多信息 → 仍要运行」即可继续。代码签名是项目的首要支出方向，签名后这个提示会消失。同时应用内更新要求发布方提供 .sha256 校验附件，缺失即拒绝自动安装。

和 Claude Code、Codex CLI 这类终端 Agent 有什么不同？+

差异在产品形态与使用方式，不在逐条功能清单。终端工具强在脚本化与 CI 集成，SkySheep 强在看得见、管得住、够得着：图形界面中文优先，权限确认、检查点回滚、白名单管理全部图形化，人不在电脑前也能用手机审批确认卡。

反过来，如果你要的是脚本化嵌入 CI、纯键盘效率流，终端 Agent 仍是更顺手的形态。SkySheep 内置无头模式与终端 REPL 作为补充。
