## 目标

帮非法律专业的用户在签合同前看懂合同：逐条标出「对自己不利 / 含义模糊 / 缺失」的条款，说清风险在哪、建议怎么谈。产出的是参考意见，不是法律意见书。

## 使用时机

- 用户给来合同、协议、条款文件（docx / pdf / 文本），说「帮我看看有没有坑」「这份能签吗」。
- 用户正在谈判，需要一份「哪些条款要争取改」的清单。

## 执行步骤

1. **确认立场**：先问清用户是哪一方（甲方/乙方/买方/卖方）——同一条款立场不同风险完全相反。再问最在意的点（钱、时间、违约后果、知识产权）。
2. **通读全文**：用 `read_file` 读取全文（PDF 也能读），先扫结构：双方义务、金额与付款、期限、违约责任、知识产权、保密、争议解决、终止与退出。
3. **逐条核查**：重点核对——付款节点与验收标准是否对等、违约金是否单边、自动续约条款藏在哪、知识产权归属是否默认归对方、终止条件是否对称、管辖地是否在对方老家。
4. **标注风险**：每条风险标级别（高 = 可能造成实质损失 / 中 = 明显不利 / 低 = 建议优化），引用原文条款编号，用人话解释后果，给出修改建议文本。
5. **产出清单**：按下面格式输出，用户需要留档时用 `write_document` 存 docx。

## 输出格式

```markdown
# 合同风险清单：<合同名称>（我方立场：<甲方/乙方>）

## 一句话结论
<能不能签：可直接签 / 建议改后再签 / 风险较大需谨慎>

## 高风险
- **条款 X.Y（原文摘录）**：<风险说明> → 建议：<修改文本或谈判方向>

## 中风险 / 低风险
- …

## 缺失条款提醒
- <这份合同没写但应该写的：如「验收不通过怎么退钱」>

## 谈判要点（按优先级）
1. <最该争取的一条，附话术建议>
```

## 注意事项

- 开头明确声明：这是文本风险参考，不构成法律意见；大额或涉及人身、股权的合同建议咨询执业律师。
- 只基于合同原文分析，不脑补口头承诺；用户提的口头约定提醒「写进合同才算数」。
- 引用条款必须带编号或原文摘录，方便用户定位；不改写原文误导用户。
- 金额、期限、比例逐个核对前后是否一致（正文与附件、大写与小写），不一致本身就是风险点。
- 涉及个人隐私、商业机密的内容提醒用户脱敏后再粘贴给第三方工具。

## 常见问题

- 用户只贴了半份合同：提醒缺失部分可能恰有关键条款，尽量补全；只能看部分时注明「结论仅基于所给片段」。
- 用户问「这样合法吗」：不下法律结论，说「该条款常见/少见/通常争议在……，是否有效请律师判断」。
- 格式混乱的扫描件：读不出文字时告知用户换个可复制文本的版本，不要硬猜。
- 用户赶时间只想要结论：先给「一句话结论 + 前三条高风险」，再展开清单。
- 对方不肯改任何条款：给「接受前可以做的小动作」建议（留证据、付款走对公、分批验收），降低执行风险。
