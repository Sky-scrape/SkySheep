## 目标

把一份原始表格变成一份有结论的数据分析报告：不是罗列数字，而是回答「这份数据说明了什么、值得注意什么、建议做什么」。

## 使用时机

- 用户给来 .xlsx / .csv 文件（或含表格的目录），说「分析一下」「看看有什么结论」「出个报告」。
- 用户有具体业务问题（销量为什么跌、哪类用户流失多），希望从数据里找答案。

## 执行步骤

1. **先问目标**：拿到文件先问一句「你想回答什么问题？」——有明确问题的分析远比「都看看」有价值；用户说随便看看时，按「整体概况 → 异常点 → 可执行建议」的自选框架走。
2. **认识数据**：用 `read_file` 或 `run_command`（Python/pandas）看行数、列名、类型、缺失率、取值范围。列名的业务含义拿不准就问用户，别猜。
3. **清洗**：处理重复、缺失、格式混乱（日期格式不统一、金额带单位、类别值大小写不一）。每一步清洗都记下来，写进报告的「数据处理说明」。
4. **分析**：围绕目标问题拆 3–6 个具体问题逐一计算（分组统计、占比、趋势、对比、相关性）。数字要交叉验证：总数对得上分项、占比和为 100%、环比口径一致。
5. **可视化**：趋势用折线、对比用柱状、构成用饼图/堆叠、分布用直方，一张图只说一件事。用户需要图片时用 `run_command`（matplotlib）生成 PNG，图表标题直接写结论。
6. **写报告**：按下面格式在对话里呈现，确认后用 `write_document` 导出 docx（图表插 PNG）或附 xlsx 明细。

## 输出格式

```markdown
# 数据分析报告：<主题>

## 核心结论
- <3~5 条，每条一句话 + 关键数字>

## 关键发现
### 1. <发现标题>
<现象描述>：<数字>（图表：<文件名或表格>）
<这意味着什么>

## 数据处理说明
- 数据范围：<行数、时间跨度>
- 清洗动作：<去重 N 行 / 填补 X 列缺失 / 剔除异常值 N 条及原因>

## 建议
- <可执行的建议，注明依据哪条发现>
```

## 注意事项

- 结论必须能从数据里指出来：每个结论注明依据（哪张表、哪列、哪个数字），算不出来的不硬编。
- 相关不等于因果，措辞留余地：「与……相关」，不说「导致」。
- 样本太少、时间跨度太短时明确说结论的局限，不夸大。
- 数据里有个人信息（手机号、身份证）时提醒用户，报告里脱敏。
- 清洗会改数据时，保留原始文件不动，清洗结果写新文件。

## 常见问题

- 文件打不开或编码乱：CSV 用 `run_command` 试 GBK/UTF-8 双编码；xlsx 有多表时先列出所有 sheet 让用户选。
- 用户中途改问题：回到第 1 步重新对齐，已做的清洗通常仍可复用。
- 数据量太大读不动：用 `run_command` 分块读或先聚合再分析，别把几万行原样贴进对话。
- 用户要「汇报用 PPT」：先出报告文字版，确认后按章节转 PPT 大纲再生成。
- 结论之间矛盾：把矛盾摆到台面上（「A 指标说涨、B 指标说跌，可能因为口径不同」），和用户一起定口径，不要强行圆。
