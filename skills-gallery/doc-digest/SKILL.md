## 目标

让用户不必通读上百页文档也能抓住重点：先给一页速览（5 条核心结论），用户对哪部分感兴趣再逐章深入，每个要点都能回溯到页码。

## 使用时机

- 用户说「帮我读读这份报告」「这论文讲了什么」「总结一下这个 PDF」。
- 用户给出长文档（研究报告、白皮书、论文、合同、标书），想快速了解内容或查特定信息。

## 执行步骤

1. **读取文档**：用 `read_document` 读取用户指定的 PDF / Word 文件。先确认文档规模（页数、章节结构），超过 100 页时用 `todo_write` 建立「通读 → 速览 → 分章精读」清单分批处理。
2. **通读抓骨架**：第一遍通读重点看——封面与目录、每章开头结尾、图表和加粗内容、结论章节，建立全文脉络。
3. **一页速览**：按下方格式输出速览，核心是 5 条核心结论；每条都要标注页码（如 `(p.12)`），让用户可以直接翻原文核对。
4. **逐章展开（按需）**：用户追问某章或某话题时，再精读对应章节，输出更细的展开：章节论点、支撑数据、图表结论、与全文的关系，同样注明页码。
5. **交叉与存疑**：发现文内前后矛盾、数据可疑、翻译明显不通的地方，主动向用户指出并标注位置，不要替作者圆场。
6. **存档（可选）**：用户需要笔记时，先确认文件名和位置，再用 `write_file` 保存速览与展开笔记为 Markdown。

## 输出格式

一页速览：

```markdown
# 速览：<文档标题>

- **文档概况**：<类型 / 页数 / 作者机构 / 成文时间>
- **一句话总结**：<这份文档最想说的事>

## 核心结论（5 条）
1. <结论>（p.X）
2. <结论>（p.X）
3. ...
4. ...
5. ...

## 值得注意
- <数据亮点 / 风险点 / 与常识相悖的观点>（p.X）

## 可以继续问
- 「详细讲讲第 3 章」「p.45 的表格什么意思」「这份报告的局限是什么」
```

逐章展开：每章按「论点 → 证据与数据 → 我的评注（如有）」组织，页码随手标注。

## 注意事项

- 所有结论必须出自文档本身并标页码；文档里没有的背景知识要说明「这是补充信息，非文档内容」。
- 不要把章节标题当结论；结论应是完整陈述句，能回答「所以呢？」。
- 用户只想要某一方面（如只关心成本数据）时，速览也要围绕该需求取舍，不要面面俱到。
- 扫描版 PDF 读取质量差时如实告知用户，不要硬编内容。
- 合同、协议类文档只做摘要和条款梳理，涉及法律判断时提醒用户咨询专业人士。

## 常见问题

- 用户一次给一批文档：用 `todo_write` 列清单逐份出速览，最后补一份横向对比（观点一致与相左之处，注明各自页码）。
- 追问的问题文档里没有：明确回答「文档未涉及」；补充公开资料时要注明不是文档内容。
- 图表是扫描图片读不出来：如实说明，请用户提供关键页截图或原始数据来源。
- 用户要求逐章全文精读：用 `todo_write` 建章级清单，每章展开后小结一次再继续，避免一次性输出过长。
- 文档版本更新了：提醒用户文件名或时间变化，按新版重新速览，不要沿用旧版结论。
