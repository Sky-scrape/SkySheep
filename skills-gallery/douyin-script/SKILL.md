## 目标

帮用户从「有想法」到「能开拍」：脚本读起来就是说话的语气，开头三秒留得住人，每条 30–60 秒讲清一个点。

## 使用时机

- 用户做短视频（抖音/视频号/小红书），要口播脚本、分镜或选题。
- 用户给了产品、知识点或热点，想拍成短视频。

## 执行步骤

1. **对齐账号**：问清账号定位（给谁看）、人设语气（专业 / 接地气 / 幽默）、 typical 视频时长、有没有过往爆款可参考（有就让用户发文案来 `read_file` 分析）。
2. **定选题**：一个视频只讲一个点。用户没选题时按「痛点 / 反常识 / 干货清单 / 热点跟进」四个方向各出 3 个候选，附一句「为什么能火」的判断。
3. **写开头**：前 3 秒必须给出「继续看的理由」——抛结论、给反差、戳痛点或立承诺；不写「大家好」式的自我介绍开头。
4. **写正文**：按「总-分-总」：一个观点配一个例子或演示动作，口播稿写成说话的句子（短句、口语词、别用书面连接词），标注分镜提示（【特写产品】【切屏幕录制】）。
5. **配发布件**：每条脚本配标题（20 字内带钩子）、正文文案、3–6 个话题标签、封面文字（8 字内）。
6. **批量交付**：多条脚本用表格汇总（选题 / 开头钩子 / 核心卖点），用户选定后再展开成完整脚本。

## 输出格式

```markdown
# 脚本：<选题>（时长约 N 秒 | 人设：<语气>）

## 开头（0–3s）
<口播稿>【画面：<分镜提示>】

## 正文
1. <要点一>：<口播稿>【画面：…】
2. <要点二>：<口播稿>【画面：…】

## 结尾（引导互动）
<口播稿：引导关注/评论，给具体互动理由>

## 发布件
- 标题：…
- 话题：#… #… #…
- 封面字：…
```

## 注意事项

- 口播稿写「说的话」不写「书面文章」：出声读一遍，拗口就改短句。
- 不夸大不违规：疗效、收益承诺（「月入过万」「三天见效」类）主动提示平台违规风险并给合规替代句。
- 热点选题提醒时效，注明热点出处；蹭热点不碰灾难、争议人物等敏感题材。
- 数据引用注明来源与时间；拿不准的数字用「约/量级」表述，不编精确数。
- 一次给多版开头供用户挑选，开头决定完播，值得多花笔墨。

## 常见问题

- 用户说「随便写个」：先给 3 个选题方向让用户挑，选题没对齐之前不写全文。
- 产品卖点太多塞不下：只留「用户最痛的一个点」，其余做成系列（这是系列化的好机会，顺带给排期建议）。
- 用户要「爆款保熟」：不承诺数据，只讲方法依据（钩子类型、选题逻辑），数据受账号权重与投放影响。
- 出镜困难：给口播替代方案（录屏 + 配音、图文轮播、纯字幕），脚本同步改写。
- 同行已拍过同题：找差异角度（人群细分 / 场景细分 / 反着说），不回避撞题但避开同质表达。
