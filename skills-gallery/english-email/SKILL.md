## 目标

帮用户发出得体的英文邮件：准确传达原意，语气匹配场景和收件人关系，用词地道不机翻，并让用户从中学到「为什么这么写」。

## 使用时机

- 用户说「这封邮件帮我翻成英文」「这封英文邮件帮我润色」「用英文回复客户说……」。
- 用户粘贴英文草稿（或中文意思），希望按特定语气改写。

## 执行步骤

1. **弄清场景**：确认四件事——
   - 邮件目的（催进度 / 道歉 / 谈判 / 感谢 / 请假 / 陌生开发信）；
   - 收件人关系（上级、客户、合作伙伴、陌生首次联系），决定语气档位；
   - 有没有前文语境（上一封邮件、会议背景），用户给文件时用 `read_file` 读取；
   - 特殊要求：英式 / 美式拼写、必须包含或回避的表述、称呼格式。
2. **写三个语气版本**：按下方格式输出正式 / 中性 / 轻松三版，各自完整可用；用户在提问时已明确指定语气，则主写该版本，另附一版供对比。
3. **解释关键用词**：每版后面用 3–5 条注解解释有讲究的地方——为什么用 `appreciate` 而不是 `want`、`per my last email` 为什么慎用、委婉语气（would / could / might）的分量差异、催促怎么写才不冒犯。
4. **交付**：正文以 Markdown 代码块给出，方便复制；用户要改某处时按意见修订。需要存档时先确认文件名与位置，再用 `write_file` 保存为 .md。

## 输出格式

````markdown
## 版本 1：正式（Formal）——适合上级、重要客户、首次联系

```text
Subject: <主题行>

Dear Mr./Ms. <姓氏>,

<正文：段落 2–4 行，一段一个意思>

Best regards,
<姓名>
```

## 版本 2：中性（Neutral）——日常同事、熟悉客户

```text
Subject: <主题行>

Hi <名字>,

<正文>

Best,
<姓名>
```

## 版本 3：轻松（Casual）——关系近的同事、长期合作方

```text
Subject: <主题行>

Hey <名字>,

<正文>

Cheers,
<姓名>
```

## 用词说明
- **appreciate it if you could...**：比 "please" 更客气，适合请求他人帮忙的场合。
- **...**：<解释语气或文化差异>
````

## 注意事项

- 忠实传达原意：中文里的模糊表述（「尽快」「原则上」）翻译前和用户确认到底多急、多硬。
- 催促和拒绝类邮件优先用委婉句式（would / could / unfortunately / I'm afraid），但不要弱化到失去立场。
- 主题行具体化（含项目名或事项），不写空泛的 "Hi" 或 "Important"。
- 不虚构事实：邮件里出现的数字、日期、承诺必须来自用户提供的信息，缺的用占位符标出让用户补。
- 收件人是多人或抄送有领导时，提醒用户注意语气是否适配最正式的那位读者。
