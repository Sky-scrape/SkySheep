## 目标

把乱糟糟的文件夹（下载目录、桌面、项目目录）整理成结构清晰、命名规范的状态：方案先给用户过目、批准后才动手，整理完留一份可追溯的报告。

## 使用时机

- 用户说「帮我整理这个文件夹」「下载目录太乱了」「桌面清理一下」。
- 用户想按规则批量移动 / 重命名文件，又担心误删误移。

## 执行步骤

1. **扫描目录**：用户指定路径后，用 `list_dir` 查看顶层结构，必要时用 `glob` 按扩展名统计文件分布。汇总一份现状报告：文件总数、总大小、按类型（文档 / 图片 / 视频 / 压缩包 / 安装包 / 代码）的数量分布、明显的问题（重复文件名、无后缀文件、混乱命名）。
2. **发现特殊情况**：留意三类高危对象——可执行文件（.exe / .msi / .bat / .sh）、系统或程序目录特征（AppData、Program Files、含 node_modules / .git 的目录）、看起来含个人数据的文件（身份证照片、账单）。遇到这些先单独提醒用户，默认不碰。
3. **提出方案**：给出分类方案让用户选择或组合——
   - 按类型：文档 / 图片 / 视频 / 压缩包 / 安装包……（适合下载目录）；
   - 按日期：YYYY-MM 年月文件夹（适合照片、按月归档的报表）；
   - 按项目：按文件名里的项目关键词聚类（适合工作目录）；
   - 附带命名规范建议（如 `YYYYMMDD_项目_描述.ext`），是否重命名由用户定。
   方案里写清每个文件去哪、哪些文件不动、哪些疑似重复（只列出不删，删除永远由用户自己做）。
4. **确认计划**：把完整移动清单（每条：原路径 → 新路径）展示给用户，明确询问「确认执行吗」。**没有得到明确同意绝不执行任何移动。**
5. **执行移动**：用户批准后，用 `move_file` 工具按清单逐条移动（一条一个文件）。
   **不要用 `run_command` 调 `mv` / `move`**：那样绕过了权限门、也进不了检查点，用户点
   「撤销本轮改动」时无法回滚。`move_file` 的安全约定：目标已存在时报错而不覆盖
   （工具层直接拦下，不需你自己先查）；因此遇到目标重名就跳过并记进报告的「跳过」表，
   确实要覆盖时必须先向用户单独确认，再显式传 `overwrite=true`。
   需要新建分类目录时用 `make_dir`，不要用 `run_command` 建目录。
6. **生成报告**：整理完成后用 `write_file`（先与用户确认文件名和位置）在目录里保存整理报告。

## 输出格式

整理报告：

```markdown
# 文件整理报告（<目录路径>）

- 时间：<YYYY-MM-DD HH:MM>
- 方案：<按类型 / 按日期 / 按项目>

## 已移动（N 项）
| 原路径 | 新路径 |
| --- | --- |

## 跳过（M 项）
| 文件 | 原因（目标重名 / 高危类型 / 用户指定不动） |
| --- | --- |

## 建议用户自行处理
- <疑似重复 / 无用安装包清单，只列出，不代删>
```

## 注意事项

- 铁律：只移动、不删除、不覆盖；删除操作永远留给用户自己做（不建议调用 `delete_file`）。
- 移动必须用 `move_file` 工具（可回滚），不要用 `run_command` 绕道。
- 移动前必须展示完整计划并获用户明确同意；执行中每步可中断。
- 不整理系统目录、程序目录和含 `.git` 的仓库目录；用户坚持时再次确认风险。
- 可执行文件、脚本默认归入「不动」清单，防止破坏软件或误放恶意文件。
- 跨盘移动大文件耗时较长，提前告知用户；移动少量试运行后再全量执行也是好办法。
- 遇到非 UTF-8（如 GBK）编码的文本文件，`read_file` 会标出编码；这类文件能读能改，
  但不要把它整个重写成 UTF-8，除非用户明确要求转码。

## 常见问题

- 目录文件上千个：先给按类型的文字版统计概览，让用户只审大类规则，不必逐文件确认。
- 用户只想整理部分子目录：明确边界（哪些子目录不进方案），并把排除项写进计划。
- 文件名乱码或编码异常：归入「建议用户自行处理」，不猜测内容强行归类。
- 整理到一半用户叫停：立即停止后续步骤，报告已完成与未完成部分，目录停留在一致的中间状态。
