## 目标

把「裸面」变成「有备而来」：围绕目标岗位预测最可能被问的问题，每个都备好答案要点和追问应对，并留一份可复查的准备文档。

## 使用时机

- 用户有面试（社招/校招/转岗），给了 JD 或岗位名，要准备问题和答案。
- 用户想模拟面试问答，或复盘上一场面试哪里答得不好。

## 执行步骤

1. **对齐信息**：收集四样——JD 原文（`read_file` 读取或粘贴）、简历（有 `resume-polish` 技能产出的优化版更好）、面试轮次（一面技术 / 二面主管 / HR 面）、离面试还有几天（决定准备深度）。
2. **拆 JD**：把 JD 拆成「硬性要求 / 加分项 / 隐含期待」，逐条对照简历找证据点（哪段经历能证明）和短板点（没有就要准备说辞）。
3. **预测问题**：按四类各出 3–6 题——经历类（简历必被问的）、技术/专业类（按 JD 关键词）、情景类（「如果遇到…你会怎么办」）、动机类（为什么来 / 为什么离开）。
4. **写答案要点**：经历类用 STAR（情境-任务-行动-结果，结果带数字）；答案写成要点不写成台词，面试要用自己的话说。每题附「可能追问」1–2 条及应对。
5. **模拟追问**：用户选几题，Agent 扮演面试官连环追问（追细节、追数据、追失败原因），练到要点能脱稿。
6. **交付**：全套问答用 `write_document` 存 docx 或 `write_file` 存 Markdown，方便面试前最后一遍过。

## 输出格式

```markdown
# 面试准备：<岗位>（<轮次> | 距面试 N 天）

## 必被问的 5 题
1. **<问题>**
   - 要点：<STAR 要点，结果带数字>
   - 追问：<可能的追问> → <应对>

## 短板与说辞
- <JD 要求但简历没有的>：<诚实承认 + 关联能力 + 学习计划>

## 反问环节（准备 3 个）
1. <问团队/业务/成长的问题，别问薪资以外百度能得到答案的>
```

## 注意事项

- 答案只基于用户真实经历整理，不编造经历和数据——追问两层就会穿帮。
- 短板策略是「诚实 + 关联 + 计划」，不是教用户隐瞒或夸大。
- 薪资谈判只给市场行情参考（需检索时注明来源与时间），具体报价策略让用户自己定。
- 涉及现雇主的敏感信息（未公开项目、薪酬）提醒用户面试中注意保密义务。
- 面试前一晚的重点是过「必被问 5 题」和反问清单，别贪多刷新题。

## 常见问题

- 用户不给 JD：按岗位常见要求整理通用题库，并请用户面试前拿到 JD 再补一轮针对性准备。
- 简历和 JD 差距大：直说差距并给两个选择——降低目标岗位或拉长准备期补证据，不灌鸡汤。
- 用户背答案背成复读机：提醒答案只留要点，模拟环节专治背诵（临时加追问打断）。
- 群面/无领导小组：补充角色策略（时间官/总结官）与发言框架。
- 面完要复盘：请用户回忆每题实际回答，对照准备要点找差距，产出复盘清单供下一场用。
