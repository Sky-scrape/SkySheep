## 目标

把「每天刷半小时信息流」压缩成「三分钟读完一份简报」：重点新闻、关键变化、各方观点，每条都有出处，看完就知道发生了什么、要不要深究。

## 使用时机

- 用户说「帮我追踪这个领域的动态」「出一份行业简报」「最近XX有什么新闻」。
- 用户想配定时任务，每天/每周自动生成某话题的简报。

## 执行步骤

1. **定范围**：和用户确认——主题边界（「AI」太大，「AI 编程助手」刚好）、时间窗（近一周 / 近一月）、关注角度（产品动态 / 融资 / 政策 / 技术进展）、语言范围（中文圈 / 含英文源）。
2. **多路检索**：`web_search` 按「主题 + 时间限定词」多组关键词检索（产品名、公司名、政策名分开搜）；重要条目用 `web_fetch` 点开原文核实，标题党标题以正文为准。
3. **筛选去重**：同一事件多家报道只留一条（选最权威或最详实的来源），转载不计入；广告软文和内容农场剔除。
4. **组织简报**：按「本期重点（≤5 条）→ 时间线 → 不同观点 → 值得跟进」组织，每条附来源链接与日期。
5. **周期化（可选）**：用户要定期收到时，说明可以用定时任务每天/每周自动跑一遍本技能并保存到指定位置，征得同意后帮用户配置（写文件与定时配置都会走确认）。

## 输出格式

```markdown
# <主题>动态简报（<时间窗>）

## 本期重点
1. **<事件一句话>**：<两三句说清>（来源：<媒体> <日期> <链接>）

## 时间线
- <日期>：<事件>

## 不同观点
- 观点 A（<谁>）：<立场与依据>
- 观点 B（<谁>）：<立场与依据>

## 值得跟进
- <悬念/待验证的事，下次简报跟踪>
```

## 注意事项

- 每条信息必须带来源与日期，检索不到出处的传闻标注「未经证实」，不混进正式条目。
- 区分事实与观点：事实进时间线，评论进「不同观点」，不把评论当事实转述。
- 时效信息注明查询时间；检索结果与用户认知冲突时如实呈现并给双方来源。
- 简报贵短：本期重点不超过 5 条，超过说明范围没切窄，先收窄再产出。
- 定时任务的预授权走任务编排的授权流程，涉及写文件的先确认保存位置。

## 常见问题

- 搜出来的都是旧闻：加时间限定词重搜（「2026」、「最近一个月」），并提醒免费搜索对极新事件可能有延迟。
- 主题太大信息爆炸：拆子话题分别搜，或按用户最关心的一个角度先切一刀。
- 中英文源矛盾：两个都列，标明各自立场与可信度差异，让用户自行判断。
- 用户想要「日报式固定栏目」：固定结构 + 周期任务组合是正解，帮用户把输出格式模板化后配置定时任务。
- 重要事件需要即时报：说明定时任务的最小周期，超高时效需求建议用户关注专门信源，简报定位是「汇总」不是「秒级推送」。
