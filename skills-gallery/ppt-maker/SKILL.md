---

## 目标

帮用户快速得到一份结构清楚、能拿去讲的 PPT：先在对话里把大纲定对，再生成文件——大纲错了做得再漂亮也白做，顺序不能反。

## 使用时机

- 用户说「做个 PPT」「把这份材料变成幻灯片」「帮我出一版汇报用的演示」。
- 用户给了主题、提纲、文档或报告，需要转成演示文稿。

## 执行步骤

1. **对齐场景**：确认四件事——给谁看（领导汇报 / 客户提案 / 教学分享）、讲多久（决定页数：约每分钟 1 页）、场合语气（正式 / 轻松）、有没有必须包含的内容（数据、截图、既定章节）。
2. **整理素材**：用户给了文档就用 `read_file` 读取提炼；需要外部事实（行业数据、竞品信息）用 `web_search` 检索并注明来源。
3. **大纲先行**：按「封面 → 目录 → 现状/背景 → 核心内容（2~4 章，每章 2~4 页）→ 总结 → Q&A」搭骨架，在对话里先给纯文字大纲请用户确认。每页写清「页标题 + 要点」。
4. **逐页生成**：确认后用 `write_document` 生成 .pptx。每页遵守：一个观点、要点不超过 5 行、每行不超过 20 字；数字放大突出；避免整段文字上墙。
5. **交付说明**：给用户列出每页讲了什么、建议讲法（哪页详讲、哪页跳过），用户要改哪页就改哪页重新生成。

## 输出格式

大纲确认环节：

```markdown
# PPT 大纲（共 N 页 | 场景：<汇报/提案/分享>）
1. 封面：<主标题 + 副标题>
2. 目录：…
3. 背景与现状：<要点>
4. 核心章节 A
   4.1 <页标题>：<要点 1 / 要点 2>
   …
N. 总结与下一步
```

## 注意事项

- 大纲必须先确认再生成文件，避免整套返工。
- 内容忠于原始材料：材料里没有的数据不要编，需要补充的用检索并标注来源。
- 汇报类 PPT 的每一页回答一个问题：「所以呢？」——没有信息量的过渡页宁可不设。
- 生成前确认保存路径与文件名；覆盖已有文件前必须征得同意。
- 用户只给一个词的主题（如「做个 AI 分享」）：先给 2 版不同侧重的大纲让用户挑，别闷头做。

## 常见问题

- 材料太长塞不下：按「听众最关心的 3 个问题」取舍，其余放进备用页（附录），正文页数不膨胀。
- 用户要求「好看的模板」：write_document 生成的是结构清晰的朴素版式；要品牌模板时建议用户在 PowerPoint 里套母版，或把生成内容按页导出方便粘贴。
- 图表需求：数据图用 `run_command`（matplotlib）出 PNG 再插入；示意图建议用户用形状工具补，Agent 侧说明图意即可。
- 中途要改结构：回到大纲层改，确认后再重新生成，不要在页级别缝缝补补。
- 用户要英文版：先中文定稿再整体翻译，术语对照表让用户过目。
