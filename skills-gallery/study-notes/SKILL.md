## 目标

让「存了很多材料但从没看懂」变成「一份能复习的笔记」：概念讲清、例子落地、附自测题——读完能合上书复述，才算学会。

## 使用时机

- 用户给来学习材料（文章、教材章节、课程文稿、PDF），说「帮我整理笔记」「带我学这个」。
- 用户备考或学新技能，希望有结构化笔记 + 自测题。

## 执行步骤

1. **摸底**：问三件事——学到什么程度（零基础 / 有基础查漏）、目标（考试 / 面试 / 实用）、笔记要多细（速览卡片 / 章节详记）。
2. **读取材料**：`read_file` 读取文件；材料太长先列章节让用户选重点；用户给主题没有材料时，用 `web_search` 找权威入门资料并注明来源。
3. **提炼结构**：按「概念 → 原理 → 例子 → 易错点」整理。概念用自己的话重新表述（术语只在首次出现时标注原文）；例子优先用材料里的，不够就编生活化类比并标注「类比，非原文」。
4. **配自测题**：每个核心概念配 1–2 道自测（问答题优于选择题），附答案与「答错说明什么没掌握」。
5. **交付**：Markdown 笔记直接呈现或 `write_file` 存到用户指定位置；要打印复习时用 `write_document` 导出 docx。用户需要记忆卡（问答分离）就按「正面问题 / 背面答案」分两栏给。

## 输出格式

```markdown
# 学习笔记：<主题>

## 一图总览
<用 5 行以内说清整体框架：这是什么、分几块、块之间关系>

## 核心概念
### <概念名>
- **一句话**：<用大白话讲清>
- **展开**：<原理/步骤>
- **例子**：<具体例子>
- **易错点**：<常见误解>

## 自测
1. <问题>（答案：<答案>；答错回看：<章节>）
```

## 注意事项

- 讲解优先「人话」，术语解释给对照；检测标准是「没学过的人能否读懂」。
- 忠于材料原意：材料与通识冲突时注明分歧，不悄悄替作者圆场。
- 不替用户学：自测题鼓励用户先答再看答案；用户要「直接给答案版」就生成但提醒复习效果会打折。
- 长材料分批整理（每批一个主题），避免一次塞满上下文导致后半段质量下降。
- 用户开启记忆时，征得同意后用 `memory_write` 记住学习目标与程度，下次接着教。

## 常见问题

- 材料是视频没有文稿：请用户提供字幕/文稿文件，或说明只按标题大纲整理；不要凭视频标题编内容。
- 用户说「全都要」：按「总览 → 每章速记卡 → 重点章节详记」分层交付，先总览再问哪里展开。
- 概念互相引用绕：在笔记开头给「阅读顺序建议」（先学哪块再学哪块）。
- 用户备考时间紧：直接按「高频考点」组织（用检索辅助判断考点权重），标明取舍依据。
- 学科性强（医学/法律）：注明笔记不能替代专业训练与权威教材，关键结论回指原始材料。
