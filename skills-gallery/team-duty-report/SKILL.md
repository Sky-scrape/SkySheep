## 目标

让团队模式无人值守自动运转：定时任务到点按「团队模板」建队、AI 总管带队员自动跑完一轮，把值班报告交付到报告目录——用户上班时报告已经在等他。

## 使用时机

- 用户说「想让团队每天早上自动出报告」「定时跑一个团队」「值班报告自动生成」。
- 用户已经会用团队模式（建队、频道、工单板），想把某类团队工作常态化定时跑。

## 执行步骤

1. **问清值班内容**：报告看什么（项目进展 / 数据指标 / 仓库动静 / 行业动态）、几点出、给谁看。值班报告贵在固定：范围越固定，模板与人设越稳。
2. **先建队并另存为模板**：无人值守只能引用「AI 总管模板」——先在会话里正常建队（总管选 AI 模型），试跑一次确认分工顺当，再用团队卡上的「另存为模板」存档（存进 `~/.skysheep/teams.json`，由引擎维护，不要手改文件）。模板只存角色配置（总管与各队员的模型、名字、一句话人设），任务指令不进模板。
3. **给出值班团队模板建议**：按下文「值班团队模板建议」一节，按用户的值班内容裁剪角色分工与人设，帮用户把人设文案写好。
4. **指导在自动化页建任务**：右面板「自动化」新建定时任务，任务形态选「团队 —— 按团队模板建队，AI 总管带队员协作」，选刚存的团队模板（表单会即时校验：模板存在、是 AI 总管、成员非空），「任务指令」就是发给总管的首条指令（例：「按值班检查单出今天的值班报告：……」）。三点注意：
   - 任务形态创建后不可修改，要换形态请删除后重建；
   - 团队任务不支持导出为系统计划任务（Windows 任务卡上的「⊞」入口一期不支持团队形态），只在 SkySheep 运行期间触发；
   - 「完成后推送到聊天渠道」只推状态摘要与结果节选，报告全文不出站。
5. **定权限档位（预授权工具）**：与所有定时任务同一套勾选，两档配法——
   - **只读档**：什么都不勾。只读工具本来就自动放行，写 / 执行类运行时一律自动拒绝。适合只汇总不落盘的值班报告（报告由引擎落盘，不需要队员写文件）。
   - **白名单档**：只勾确需的工具（如 `fs.write_file` 让队员把中间素材写进工作区）。名单外一律自动拒绝；勾选 `run_command` 等于允许无人值守执行任意命令，任务指令不完全可信就不要勾。
   - 无人值守守卫照走：删除类操作、引擎数据目录写入、出站密钥都会被拦，预授权压不住这三道。
6. **试跑与校准**：建好后先「立即运行」一次，到 `<项目>/.skysheep/reports/` 读 `cron-team-*.md` 交付说明，按产出回头调模板人设与任务指令。

## 值班团队模板建议

**角色分工**（AI 总管 1 名 + 队员 ≤3 名；队员上限默认 3，可在 设置 · 团队 调整）：

- **AI 总管**：持「值班检查单」——把今日值班拆成固定几道工单、逐单派工、验收回报、汇总交付。人设强调「报告类团队少开小会，分歧自行裁定」，省全局轮次（上限 40 轮，总管轮 / 成员轮 / 小会合计）。
- **队员 A · 信息哨**：负责收集——读工作区文件、报告目录，预授权允许时联网检索，产出带出处的原始素材。
- **队员 B · 核对员**：负责把关——对素材做交叉核对、口径统一、风险标注，产出可引用的分节草稿。
- 只要一份汇总时用「总管 + 1 队员」最省轮次；素材面广（多来源 / 多目录）再上三人编队。

**频道用法**：

- 派单与回报全走团队频道：总管派单 @队员，队员完成后在频道回报结论。频道消息是纯文本，任何情况下不会被执行。
- 队员各自独立工作记忆、互不可见，全靠频道互通——人设里写明「回报带数据出处」，核对员才对得上口径。
- 分歧三级处理：队员间频道互聊自行解决 → 谈不拢 @总管裁定 → 重大分歧才开小会。小会计入全局轮次，例行报告尽量在前两级消化。

**交付报告结构**（《交付说明》的成果汇总 / 各队员贡献 / 未尽事项三段是引擎固定结构，正文按值班需要组织）：

- 头部元信息由引擎自动生成：任务名、模板名、触发方式、终态、轮次消耗、工单板快照、逐成员用量。
- 正文建议四段：**值班速览**（≤5 条要事）→ **分项动态**（按检查单逐项）→ **数据表**（关键指标，有数才写数）→ **风险与待办**（含未尽事项）。

## 输出格式

帮用户起草配置材料时按下面两块交付：

```markdown
# 团队模板建议（<模板名>）
- 总管：<模型>——<一句话人设，含「少开小会、按检查单推进」>
- 队员A <名字>：<模型>——<一句话人设，含回报要求>
- 队员B <名字>：<模型>——<一句话人设>

# 任务指令（粘进自动化页「任务指令」）
<发给总管的首条指令：值班范围、检查单逐项、报告四段结构、交付要求>
```

## 注意事项

- Agent 不能替用户点界面：另存为模板、新建定时任务、勾预授权都在界面上完成，本技能负责备好材料、讲清每一步。
- 全员模型不可用或总管构建失败会按失败收尾，不会建注定空转的团队；部分成员不可用照常失败隔离（工单标出错、总管改派）。
- 防失控上限只有一套：全局轮次 40、打回 2 次、队员停滞移交、单成员单轮 5 分钟超时、每日 token 预算。轮次耗尽 / 预算越线是设计内停机——交付说明照出、带未尽事项，不是故障。
- 总管空闲会自动补发续跑指令（默认 1 次，0 = 空闲即收队），仍空闲则收队并记未尽事项。
- 交付说明全文落 `<项目>/.skysheep/reports/cron-team-*.md`；任务行与渠道推送只留摘要。

## 常见问题

- 模板下拉是空的：先在会话里建队并「另存为模板」。用户总管模板不能用于无人值守——每条消息都等用户指令，到点只会空转。
- 到点报「团队模板已不存在」：删模板不级联删任务，触发时才报错；删模板时同步清理引用它的定时任务。
- 想改任务形态：不支持就地改，删除后重建。
- 电脑关机错过触发：下次打开应用补跑一次；要开机即跑就开 设置 · 高级 的「开机自动启动」。
- 报告质量不稳：把检查单逐项写进任务指令（固定栏目式），范围收窄到模板能稳定覆盖的程度；别指望队员自由发挥。
- 上一轮没跑完又到点：不会并行重跑，在跑期间到点只记一次「跳过」，下个周期照常触发。
