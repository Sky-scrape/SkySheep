## 目标

写出适合微信公众号发布、可读性强的中文新媒体文案：标题吸引人但不标题党，结构适配手机阅读，观点清楚、有记忆点。

## 使用时机

- 用户说「帮我写篇公众号文章」「写一篇推文」「这个选题怎么写」。
- 用户给出素材（文章、数据、个人经历），希望加工成公众号推文。

## 执行步骤

1. **选题沟通**：向用户确认五件事——
   - 主题与核心观点（这篇文章最想让读者记住什么）；
   - 目标读者（写给谁看，决定用词和案例）；
   - 公众号定位与往期风格（用户给得出往期文章时，用 `read_file` 或 `web_fetch` 读一两篇，模仿其语气）；
   - 篇幅（常见 1500–2500 字）；
   - 素材：用户提供的文件用 `read_file` / `read_document` 读取；需要行业数据、热点背景时用 `web_search` 检索并注明来源。
2. **大纲确认**：给出标题（3 个备选）+ 小标题大纲 + 每节要点，等用户选定后再动笔。用户对大纲的修改意见要落到成稿里。
3. **成稿**：按下方输出格式撰写。写完自查一遍：开头三行内是否勾住人、小标题是否扫一眼就懂、金句是否自然、结尾是否给了互动引导。
4. **交付**：正文以 Markdown 代码块交付，方便用户复制到公众号编辑器。需要存档时，先确认文件名与位置，再用 `write_file` 保存为 .md 文件。

## 输出格式

```markdown
# <标题：有信息量，适度制造好奇，不做纯震惊体>

<开头钩子：一个场景、一个反常识事实或一个提问，三行内进入正题>

## <小标题 1：短句或观点句，不要「第一部分」>
<段落：每段 3–5 行，手机上不拥挤>

## <小标题 2>
...

## <小标题 3>
...

<结尾：2–3 句收束观点 + 引导互动（「你怎么看？评论区聊聊」/ 点赞在看引导）>
```

- 金句：全文 1–3 处，用 **加粗** 标出，放在段落收尾处；宁缺毋滥。
- 小标题 3–5 个为宜；超过 3000 字要先和用户商量是否拆分。

## 注意事项

- 标题克制：可以制造好奇，但不夸大、不贩卖焦虑、不造假引数据。
- 引用的数据和案例必须有出处（用户给的素材或 web_search 结果），标注来源；查不到佐证的说法改为「一种说法是」或删掉。
- 涉及医疗、法律、金融等专业内容时提醒用户核实，必要时请专业人士审稿。
- 不写违反平台规则的诱导分享话术；遵守广告法，避免「最」「第一」等绝对化用语（引用原话除外）。
- 成稿后主动问用户是否需要调整语气（更犀利 / 更温和）或压缩篇幅。

## 常见问题

- 用户只有一句话选题：先给 3 个差异化切入角度（反常识 / 实用干货 / 故事切入）各附一句概览，选定后再走大纲。
- 用户要求「爆款」：说明爆款无法保证，能做的是把钩子、结构、金句三件事做到位；拒绝编造数据和蹭不实热点。
- 需要配图：问用户是否用 `generate_image` 生成头图或示意插画，风格和比例先确认再生成。
- 系列文章：询问是否有固定栏目结构和标签，保持各期体例一致；用户给过往期时用 `read_file` 对齐格式。
- 用户想配历史文章互推：问清要引用的篇目和引导话术，插入位置放在小标题之间而不是正文中段。
- 用户对成稿方向不满意：退回大纲层重新对齐，不要在成稿上反复小修，避免越改越散。
